```bash
ocel deploy
```

A `package.json` with no `next` or `@sveltejs/kit` in it makes the app a `node` app. On
serverless compute, ocel serves the default export through its `fetch` method.

## Entrypoint

On serverless, ocel serves the first of the
[entrypoints it looks for](/docs/configuration#the-app-at-the-project-root), and the same file
makes a project root naming no `apps` this app. Any other file, name it with
[`entrypoint`](/docs/configuration#entrypoint).

## Containers

On `compute: "container"`, and on a [VPS](/docs/providers/vps), which runs only containers, the
image runs your `start` script. Nothing serves the default export there, so the script starts a
server on `PORT`, which the container sets:

```ts title="src/start.ts"
import { serve } from "@hono/node-server";
import app from "./server";

serve({ fetch: app.fetch, port: Number(process.env.PORT ?? 3000) });
```

```json title="package.json"
{
  "scripts": { "start": "tsx src/start.ts" }
}
```

## Uploads and realtime

`ocel/bucket/hono` and `ocel/realtime/hono` shape the [bucket](/docs/sdk/bucket) and
[realtime](/docs/sdk/realtime) route handlers for Hono:

```ts
import { createRealtimeHandler } from "ocel/realtime/hono";

app.all("/api/realtime", createRealtimeHandler(rt));
```

## Limitations

On serverless, the build bundles the entrypoint, so the function gets only what it imports. Files
read at run time get left behind. The build lists the sources that read them. Copy them in
yourself, or build with `OCEL_BUILD_PREFER_TRACING=1`, which copies the dependency tree instead.
