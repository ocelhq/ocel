```bash
ocel deploy
```

Ocel deploys the app as a `node` app. On serverless compute, ocel serves the default export
through its `fetch` method.

## How ocel finds the app

A directory is a node app when its `package.json` sits beside one of these files. Ocel serves
the first it finds:

`src/server`, `src/index`, `src/app`, `index`, `server`, `app`, `src/main`, each with `.ts`, `.mts`, `.cts`, `.js`, `.mjs` and `.cjs` in turn

On serverless, the build bundles from that file, so it is the one file the app needs. The file is
also what tells an app from a `package.json` that only holds tooling, such as the SDK of a project
that declares only resources. A `package.json` that depends on `next`, `@sveltejs/kit` or
`@nestjs/core` is that framework's app instead, whatever files sit beside it.

Ocel deploys a directory only when exactly one framework matches it. A `pyproject.toml` or
`go.mod` beside the Hono app is fine while it holds no app. If it holds a
[Python](/docs/frameworks/python#how-ocel-finds-the-app) or
[Go](/docs/frameworks/go#how-ocel-finds-the-app) app, both match, so ocel deploys neither and
`ocel doctor` names the two. List the app under `apps` with `framework: "node"` then.

If your server lives anywhere else, name the file with [`entrypoint`](/docs/configuration#apps).
Detection does not read `entrypoint`, so set `framework: "node"` beside it.

## Containers

On `compute: "container"`, and on a [VPS](/docs/providers/vps), which runs only containers, the
image runs your `start` script. Nothing serves the default export there, so the script starts a
server on `PORT`, which the container sets:

```ts title="src/start.ts"
import { serve } from "@hono/node-server";
import app from "./server";

serve({ fetch: app.fetch, port: Number(process.env.PORT ?? 3000) });
```

```json title="package.json"
{
  "scripts": { "start": "tsx src/start.ts" }
}
```

## Uploads and realtime

`ocel/bucket/hono` and `ocel/realtime/hono` shape the [bucket](/docs/sdk/bucket) and
[realtime](/docs/sdk/realtime) route handlers for Hono:

```ts
import { createRealtimeHandler } from "ocel/realtime/hono";

app.all("/api/realtime", createRealtimeHandler(rt));
```

## Limitations

On serverless, the build bundles the entrypoint, so the function gets only what it imports. Files
read at run time get left behind. The build lists the sources that read them. Copy them in
yourself, or build with `OCEL_BUILD_PREFER_TRACING=1`, which copies the dependency tree instead.
