Install the adapter and name it in your config:

```bash
pnpm add -D @ocel/sveltekit
```

```ts title="vite.config.ts"
import ocel from "@ocel/sveltekit";
import { sveltekit } from "@sveltejs/kit/vite";
import { defineConfig } from "vite";

export default defineConfig({
  plugins: [sveltekit({ adapter: ocel() })],
});
```

On SvelteKit 2.31 or later, set `kit: { adapter: ocel() }` in `svelte.config.js` instead.

`ocel deploy` recognises the app by its `@sveltejs/kit` dependency and runs its `build` script.
Every route renders in one function. Prerendered pages and the files in `static/` are served
beside it, and the content-hashed chunks under `/_app/immutable/` are cached for a year,
from the asset bucket wherever the edge in front reads one. `/_app/version.json` is always
revalidated, so an open tab learns of a new deployment.

To run the app in a container, give it a `"start": "node build"` script. Outside `ocel build`,
`vite build` writes to `build/`, and `node build` serves it on `PORT` at `HOST`, which is
`127.0.0.1` unless you set it.

## Environment variables

SvelteKit 3 reads its variables from the `variables` object `src/env.ts` exports. Declare them with
`defineEnvVars` from `ocel/env/sveltekit`, in a file in your
[discovery folder](/docs/configuration#discoverypaths), where ocel already looks, and
re-export that object from `src/env.ts`:

```ts title="resources/env.ts"
import { defineEnvVars } from "ocel/env/sveltekit";
import * as v from "valibot";

export const variables = defineEnvVars({
  STRIPE_KEY: { class: "sensitive", description: "Stripe key" },
  PUBLIC_API_URL: { class: "plain", public: true, schema: v.pipe(v.string(), v.url()) },
});
```

```ts title="src/env.ts"
export { variables } from "../resources/env";
```

Each variable takes `class` and `folders`, which ocel reads, beside SvelteKit's own `public`,
`static`, `schema` and `description`. SvelteKit generates the `$app/env/*` types and reads the
values from the environment, where ocel delivers each under its own name. Ocel writes nothing
into your `tsconfig.json`.

`defineEnvVars` refuses what SvelteKit would accept and ocel cannot keep safe:

- `public: true` on a class other than `plain`.
- `class: "secret"`. SvelteKit reads a value once, at startup, so a rotated secret would never
  arrive. Declare it with `defineEnv` from `ocel/env`, whose accessor reads it live.
- `static: true` on a `sensitive` variable, which would inline its value into the server bundle.

`PUBLIC_OCEL_URL` holds the URL the deployment is served from. It is in the object `defineEnvVars`
returns, so `$app/env/public` has it; declaring it yourself is refused.
