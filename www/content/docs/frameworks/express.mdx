```ts title="src/server.ts"
import express from "express";

const app = express();

app.get("/", (_req, res) => {
  res.send("Hello");
});

app.listen(Number(process.env.PORT ?? 3000));
```

```ts tab="TypeScript" tab-group="config" title="ocel.config.ts"
import { defineConfig } from "ocel/config";
import awsProvider from "ocel/providers/aws";

export default defineConfig({
  slug: "my-app",
  provider: awsProvider(),
});
```

```json tab="JSON" title="ocel.json"
{
  "$schema": "https://ocel.dev/schema/ocel.schema.json",
  "slug": "my-app",
  "provider": "aws"
}
```

```bash
ocel deploy
```

Ocel deploys the app as a `node` app. On serverless compute, `app.listen` does not open a port.
Ocel takes the server it is called on and hands it each request. Exporting the app with
`export default app` also works there.

## How ocel finds the app

A directory is a node app when its `package.json` sits beside one of these files. Ocel serves
the first it finds:

`src/server`, `src/index`, `src/app`, `index`, `server`, `app`, `src/main`, each with `.ts`, `.mts`, `.cts`, `.js`, `.mjs` and `.cjs` in turn

`src/main` is where `nest new` writes a NestJS server, so a NestJS app is found too.

On serverless, the build bundles from that file, so it is the one file the app needs. The file is
also what tells an app from a `package.json` that only holds tooling, such as the SDK of a project
that declares only resources. A `package.json` that depends on `next` or `@sveltejs/kit` is that
framework's app instead, whatever files sit beside it.

Ocel deploys a directory only when exactly one framework matches it. A `pyproject.toml` or
`go.mod` beside the Express app is fine while it holds no app. If it holds a
[Python](/docs/frameworks/python#how-ocel-finds-the-app) or
[Go](/docs/frameworks/go#how-ocel-finds-the-app) app, both match, so ocel deploys neither and
`ocel doctor` names the two. List the app under `apps` with `framework: "node"` then.

If your server lives anywhere else, name the file with [`entrypoint`](/docs/configuration#apps).
Detection does not read `entrypoint`, so set `framework: "node"` beside it. An app that sets
`framework: "node"` with no `entrypoint` and none of those files has nothing to bundle, so it is
refused on serverless, naming the files ocel looked for.

## Containers

On `compute: "container"`, and on a [VPS](/docs/providers/vps), which runs only containers, the
image runs your `start` script. That is why the app listens on `PORT`, which the container sets.

```json title="package.json"
{
  "scripts": { "start": "tsx src/server.ts" }
}
```

## Limitations

On serverless, the build bundles the entrypoint, so the function gets only what it imports.
`express.static` directories, view templates and files read with `fs` get left behind. The build
lists the sources that read such files. Copy them in yourself, or build with
`OCEL_BUILD_PREFER_TRACING=1`, which copies the dependency tree instead.
