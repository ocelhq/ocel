title: Express

---

```ts title="src/server.ts"
import express from "express";

const app = express();

app.get("/", (_req, res) => {
  res.send("Hello");
});

app.listen(Number(process.env.PORT ?? 3000));
```

```ts tab="TypeScript" tab-group="config" title="ocel.config.ts"
import { defineConfig } from "ocel/config";
import awsProvider from "ocel/providers/aws";

export default defineConfig({
  slug: "my-app",
  provider: awsProvider(),
});
```

```json tab="JSON" title="ocel.json"
{
  "$schema": "https://ocel.dev/schema/ocel.schema.json",
  "slug": "my-app",
  "provider": "aws"
}
```

```bash
ocel deploy
```

A `package.json` with no `next` or `@sveltejs/kit` in it makes the app a `node` app. On
serverless compute, `app.listen` does not open a port. Ocel takes the server it is called on and
hands it each request. Exporting the app with `export default app` also works there.

## Entrypoint

On serverless, ocel serves the first of these that exists: `src/server`, `src/index`, `src/app`,
`index`, `server`, `app`, each as `.ts` or `.js`. Any other file, name it with
[`entrypoint`](/docs/configuration#entrypoint).

## Containers

On `compute: "container"`, and on a [VPS](/docs/providers/vps), which runs only containers, the
image runs your `start` script. That is why the app listens on `PORT`, which the container sets.

```json title="package.json"
{
  "scripts": { "start": "tsx src/server.ts" }
}
```

## Limitations

On serverless, the build bundles the entrypoint, so the function gets only what it imports.
`express.static` directories, view templates and files read with `fs` get left behind. The build
lists the sources that read such files. Copy them in yourself, or build with
`OCEL_BUILD_PREFER_TRACING=1`, which copies the dependency tree instead.
