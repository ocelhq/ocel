---
title: Cloudflare edge
description: Put Cloudflare in front of any origin.
---

Cloudflare is an edge, not a [provider](/docs/providers): it fronts whichever provider runs
your app, and is named in that provider's options.

```ts tab="TypeScript" tab-group="config" title="ocel.config.ts"
import { defineConfig } from "ocel/config";
import { cloudflareDns } from "ocel/dns";
import { cloudflare } from "ocel/edge";
import awsProvider from "ocel/providers/aws";

export default defineConfig({
  slug: "my-app",
  provider: awsProvider({ edge: cloudflare(), dns: cloudflareDns() }),
  apps: [{ name: "web", path: "." }],
});
```

```json tab="JSON" title="ocel.json"
{
  "$schema": "https://ocel.dev/schema/ocel.schema.json",
  "slug": "my-app",
  "provider": { "aws": { "edge": "cloudflare", "dns": "cloudflare" } },
  "apps": [{ "name": "web", "path": "." }]
}
```

`dns: "cloudflare"` writes the hostname records into Cloudflare rather than the origin
provider's own DNS. It works without the Cloudflare edge too. On AWS a Cloudflare edge requires
it: Route 53 cannot write the records the edge answers on.

## Setup

Set `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` in the environment ocel runs in, such as by
exporting them in your shell; the config never holds them, and the project's `.env` doesn't reach
the provider. Create the token at
[dash.cloudflare.com/profile/api-tokens](https://dash.cloudflare.com/profile/api-tokens). A deploy
checks both before the build, and stops if either is unset or Cloudflare will not list the
account's zones for the token.

| The token needs | When |
| --- | --- |
| Zone Read, DNS Edit on the zone | always; this is all `dns: "cloudflare"` alone needs |
| Zone Settings Read, SSL and Certificates Edit, Cache Purge on the zone; Account Settings Read on the account | with the Cloudflare edge |
| Cloudflare Tunnel Edit on the account | with `tunnel` |

Unless the edge sets `tunnel`, the zone's SSL mode must be **Full (strict)**.

## What runs where

| Origin | Serverless apps | Container apps |
| --- | --- | --- |
| [AWS](/docs/providers/aws) | a worker | forwarded to a load balancer ([below](#container-apps-on-aws)) |
| [Google Cloud](/docs/providers/gcp) | a worker ([below](#apps-on-google-cloud)) | a worker ([below](#apps-on-google-cloud)) |
| [VPS](/docs/providers/vps) | — | forwarded to the box, or through a tunnel |

Forwarded means a proxied record per hostname and no worker. A promote purges what Cloudflare
cached for the hostnames it moved to the new release.

`cloudflare({ tunnel: true })` (`{ "cloudflare": { "tunnel": true } }` in JSON) reaches a VPS
box through a Cloudflare Tunnel instead of at its address, with no certificates and no SSL mode
to set; other providers refuse it. See
[through a Cloudflare Tunnel](/docs/providers/vps#through-a-cloudflare-tunnel).

ocel changes neither Always Use HTTPS nor any redirect rule in your zone: when a visitor uses
plain http, the origin answers with a redirect to https.

## Apps on Google Cloud

The worker routes each request, caches pages at the edge, and reaches every deployment of an
app, serverless or container, on its Cloud Run revision-tag URL
(`https://<release>---<service>-<hash>-<region>.a.run.app`). The edge takes no option on Google
Cloud:

```ts tab="TypeScript" tab-group="config" title="ocel.config.ts"
import { defineConfig } from "ocel/config";
import { cloudflare } from "ocel/edge";
import gcpProvider from "ocel/providers/gcp";

export default defineConfig({
  slug: "my-app",
  provider: gcpProvider({
    project: "my-project",
    region: "europe-west1",
    edge: cloudflare(),
  }),
  apps: [{ name: "web", path: "." }],
});
```

```json tab="JSON" title="ocel.json"
{
  "$schema": "https://ocel.dev/schema/ocel.schema.json",
  "slug": "my-app",
  "provider": {
    "gcp": {
      "project": "my-project",
      "region": "europe-west1",
      "edge": "cloudflare"
    }
  },
  "apps": [{ "name": "web", "path": "." }]
}
```

- Each service the worker reaches answers any caller, and refuses a request that does not
  present the tier's origin secret before the app runs. The worker sends the secret in a header,
  and the runtime takes it off before your code sees the request.
- `ocel bootstrap` keeps one origin secret per tier in Secret Manager and replaces it once it is
  90 days old. The replaced secret is still accepted for 7 days: deploy every project in the tier
  again within them. A deploy warns when the secret is due or a replacement is under way.
- A service whose name leaves no room for its revision tag (Cloud Run fits the tag and the
  service name into 46 characters) is refused before anything is deployed.
- A project deployed through the proxy before this existed is refused until `ocel projects destroy` has
  taken its deployments down.

The edge serves a stale page while the app renders a fresh one, and purges a revalidated tag. The
worker reads static files and route tables from the tier's edge bucket, which holds only what an
edge may serve, over its S3-compatible API, with an HMAC key that may read that bucket and nothing
else.

## Container apps on AWS

A container app's hostname gets a proxied record pointing at a public load balancer, one per
tier, which the first such app raises (about $16 a month plus traffic). It admits only
Cloudflare's addresses presenting your zone's client certificate, and redirects plain http to
https with a 301 (an AWS load balancer cannot send a 308). Each hostname gets an ACM
certificate, validated through the DNS writer. A container preview gets a proxied record of its own and
runs no worker.

Middleware, the edge runtime and edge caching need the worker, so a container app behind
Cloudflare is served streaming alone. A deploy that needs more is refused unless
`allowDegraded` names the need.

Limits across every project in the tier. AWS raises the first three on request, and a deploy
that reaches one is refused naming the Service Quotas entry (Elastic Load Balancing):

| Limit | Counts | Quota |
| --- | --- | --- |
| 25 certificates besides the default | each production hostname and preview wildcard | L-9365A611 |
| 100 rules | each hostname and live preview | L-7EED9B64 |
| 25 trust-store CAs | each zone forwarding to it | L-43FE5A42 |
| 100 target groups (not raised) | each release of a container app, kept ones included | — |

A certificate ocel did not request for a hostname (one reused from ACM, or the shared
`--preview` wildcard) stays on the load balancer after the hostname goes.

## Previews behind Cloudflare

A preview wildcard is forwarded through one proxied `*.<base>` record, and the origin answers
each preview under it only to Cloudflare. Universal SSL covers the zone apex and one label
below, so `*.acme-previews.com` (a zone of its own) needs nothing more. Deeper, such as
`*.preview.acme.com` in `acme.com`, needs an advanced certificate: ocel orders one and stops,
and running the same command again once Cloudflare issues it, usually within minutes, finishes.
Ordering one needs
[Advanced Certificate Manager](https://developers.cloudflare.com/ssl/edge-certificates/advanced-certificate-manager/),
a paid add-on; without it ocel refuses the wildcard.

## Origin certificate

An origin Cloudflare forwards to answers only requests that arrive with the certificate your zone
presents to origins (zone-level authenticated origin pulls, with a certificate of your own). Every
such origin trusts the CA of every client certificate the zone holds. Google Cloud is reached by the
worker with the tier's origin secret instead, and trusts no certificate of the zone.

- **Zone holds none:** ocel mints a CA and a client certificate, both good for ten years,
  uploads the certificate, has the origin trust the CA, and turns zone-level pulls on.
- **Zone presents Cloudflare's shared certificate** (global pulls on, or zone-level pulls with
  no certificate of its own): refused, since another origin may trust only that one. Upload a
  certificate of your own first.
- ocel never otherwise replaces or deletes a zone's client certificate: every origin the zone
  forwards to shares it.
- An AWS load balancer refuses the certificate once it or its CA lapses. VPS origins accept it
  past expiry, except behind your own Traefik.

**Rotating it** (or retiring a leaked key):

1. Upload the new certificate under **SSL/TLS > Origin Server > Authenticated Origin Pulls**.
   ocel must be able to read its CA: upload a self-signed certificate, or one naming its CA's
   certificate as a `data:application/pkix-cert;base64,` URI in its CA Issuers access, as ocel's
   own does. An AWS load balancer trusts only a CA, so behind one only the second kind works. A
   deploy refuses a zone holding a certificate whose CA it cannot read.
2. Cloudflare presents it at once, and origins refuse it until you deploy one project on each
   VPS box and each AWS tier with container apps the zone forwards to.
   Each origin then trusts both.
3. Delete the old certificate from the zone, then deploy every project with a hostname in the
   zone again. Each hostname's origin stops trusting the old CA when its project deploys.
