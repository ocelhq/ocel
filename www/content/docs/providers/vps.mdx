```bash
ocel init --provider vps --option ssh=my-box
```

`ssh` is a `Host` alias from your `ssh_config`, or the destination spelled out:

```ts tab="TypeScript" tab-group="config" title="ocel.config.ts"
import { defineConfig } from "ocel/config";
import vpsProvider from "ocel/providers/vps";

export default defineConfig({
  slug: "my-app",
  provider: vpsProvider({ ssh: { host: "${DEPLOY_HOST}", user: "deploy" } }),
  apps: [{ name: "web", path: ".", compute: "container" }],
});
```

```json tab="JSON" title="ocel.json"
{
  "$schema": "https://ocel.dev/schema/ocel.schema.json",
  "slug": "my-app",
  "provider": {
    "vps": { "ssh": { "host": "${DEPLOY_HOST}", "user": "deploy" } }
  },
  "apps": [{ "name": "web", "path": ".", "compute": "container" }]
}
```

```bash
ocel deploy
```

In a terminal, the first deploy offers to run `ocel bootstrap production`, and, if the project
declares no hostname, shows the line to add and waits while you save it:

```json
"domains": { "production": "my-app.example.com" }
```

In a script or CI nothing is asked, so bootstrap and declare the hostname first:

```bash
ocel bootstrap production
ocel deploy
```

## What the box needs

| Need | Why |
| --- | --- |
| SSH as root or a login with passwordless sudo, for bootstrap only | Bootstrap writes under `/etc`, `/var/lib` and `/usr/local`. Deploys then run as [`ocel-deploy`](#the-deploy-login). |
| systemd | Ocel's host services are systemd units. |
| `install`, `stat`, `sha256sum`, `flock`, `timeout`, `getent`, `groupadd`, `useradd`, `usermod`, `userdel` | Bootstrap runs them as root. |
| No Docker, or Docker 28.0+ under `docker.service` | Bootstrap installs it if missing. Snap and rootless Docker are refused. |
| Ports 80 and 443 free, and open to the internet | Ocel's proxy serves on them and gets certificates over port 80. Docker's iptables rules bypass ufw, so open them in your cloud firewall. Port taken? Go [behind your own proxy](#behind-your-own-proxy). |
| A DNS record per hostname pointing at the box | `ocel domain add` prints it, or writes it with `dns: "cloudflare"`. |

An unknown host key is shown and you are asked to record it; check it against the machine.

## Bootstrap

`ocel bootstrap <tier>` (`production` or `preview`) prepares the box once per tier. Running
it again changes only what drifted. `ocel bootstrap destroy <tier>` removes it all, except Docker and its
containers.

What lands on the box:

| What | For |
| --- | --- |
| Docker | When missing; pinned by sha256. Upgrading it is yours. |
| `"live-restore": true` in `/etc/docker/daemon.json` | A daemon restart or upgrade stops no container. See [Upgrades](#upgrades). |
| `ocel-deploy` | The deploy login. See [the deploy login](#the-deploy-login). |
| `/etc/sudoers.d/ocel-docker`, `/etc/sudoers.d/ocel-seal-<tier>`, `/etc/sudoers.d/ocel-pins` | The three commands `ocel-deploy` runs as root. |
| `/usr/local/lib/ocel/live` | The box agent: serves app containers their secret values over `ocel-live.socket`, runs topics and tasks, checks the deploy login's `docker` commands, seals values and keeps the tier's records. |
| `ocel-proxy` (Caddy) | Ports 80 and 443; gets each certificate on first connection. Not behind your own proxy. |
| `ocel-switchboard`, `ocel` network | Routes each hostname to its app. Recreated by the next deploy if pruned. |
| `/etc/ocel/<tier>/seal.key` | Seals secret values on the box. Lose it and they can't be opened. |
| `ocel-envsourcesync@<tier>.service` | Syncs [env sources](/docs/env-sources) into the tier's values each minute. |
| `/usr/local/lib/ocel/backups`, `ocel-backups.timer` | Backs up every resource daily. See [Backups](#backups). |
| `/var/lib/ocel/`, `/etc/ocel/certs` | Deploy state, routing, certificates, and the certificates you pin. |

### The deploy login

Bootstrap needs root or passwordless sudo once. It creates the `ocel-deploy` login, which
accepts the keys in the bootstrapping login's `~/.ssh/authorized_keys`, or the key `deployKey`
names. Set `ssh.user` to `ocel-deploy` and deploys need no sudo beyond three root-owned lines:

| Line | Lets `ocel-deploy` run, as root |
| --- | --- |
| `/etc/sudoers.d/ocel-docker` | `/usr/local/lib/ocel/live docker`. Every `docker` command goes through this check; `ocel-deploy` is in no group that reaches the docker socket. |
| `/etc/sudoers.d/ocel-seal-<tier>` | `/usr/local/lib/ocel/live seal <tier> seal` and `… open`, which seal and open values under `/etc/ocel/<tier>/seal.key`. The login cannot read the key. |
| `/etc/sudoers.d/ocel-pins` | `/usr/local/lib/ocel/live pin <name>`, which prints the certificate pinned at `/etc/ocel/certs/<name>.crt` and whether the key beside it matches. It never prints the key. Written only with Ocel's own proxy. |

The docker check refuses:

- privileged mode, devices and host namespaces;
- capabilities past the ones Ocel's containers use, and loosened seccomp;
- a port published beyond loopback;
- the default bridge, and a network that is neither Ocel's nor your proxy's `network`;
- `exec` and `rename` on a container Ocel does not run;
- `exec` into `ocel-proxy` of anything but the commands Ocel runs there;
- a named volume that binds a host path, and a bind mount outside the directories
  `/etc/ocel/docker.json` lists.

One deploy login serves both tiers, so a deploy key reaches production and preview alike. When
previews must not reach production, give each tier its own box.

An adopted proxy whose container mounts the docker socket (Coolify's and Dokploy's do) reads the
config `ocel-deploy` writes for it, so on such a box the deploy login can reach the socket
through it.

Ocel's own proxy reads the keys under `/etc/ocel/certs` and the keys of the certificates it
obtains, and loads the config `ocel-deploy` writes for it, so the deploy login can reach those
keys through that config.

## Domains and certificates

Ocel's proxy gets a certificate the first time a client connects to a hostname, and drops it
14 days after expiry once the hostname is gone. `ocel doctor` checks DNS and port 80.

To serve your own certificate, pin it by hostname:

```json
"provider": { "vps": { "ssh": "my-box", "certificates": { "shop.example.com": "/etc/ocel/certs/shop" } } }
```

The path names a pair directly under `/etc/ocel/certs`: Ocel's proxy loads `shop.crt` and
`shop.key` from there. A pinned certificate wins for every hostname it covers.

## Previews

```bash
ocel bootstrap preview
```

Point `*.<preview base>` (from `domains.preview`) at the box. A certificate per preview
hostname would be published in Certificate Transparency logs within minutes, revealing it, so a
preview deploy is refused until you pick one:

- pin a certificate for `*.<preview base>` under `certificates`;
- front the box [with Cloudflare](#behind-cloudflare);
- behind Traefik, set `previewResolver`; behind your Caddy, serve a wildcard certificate;
- or set `perHostnamePreviewCertificates: true` to accept that the hostnames are published.

## Behind Cloudflare

```json
"provider": { "vps": { "ssh": "my-box", "edge": "cloudflare", "dns": "cloudflare" } }
```

In TypeScript, `edge: cloudflare()` and `dns: cloudflareDns()`. Set the zone's SSL mode to
**Full (strict)**.

- Ocel writes a proxied record for each hostname and serves it with a Cloudflare origin CA
  certificate it issues and renews.
- Port 443 refuses a request that skips Cloudflare; port 80 only redirects to https.
- Previews are forwarded the same way; see
  [previews behind Cloudflare](/docs/providers/cloudflare#previews-behind-cloudflare).
- `ocel doctor` checks the hostname by requesting it through Cloudflare.

With `traefik` or `caddy`, ocel configures this in your proxy. With `manual`, you do: for each
hostname, require a client certificate chaining only to its `clientCAs` under `shields` in
`/var/lib/ocel/routing/table.json`, serve the origin certificate listed there, and redirect
port 80 to https. A deploy refuses a hostname your proxy leaves open.

### Through a Cloudflare Tunnel

Set `tunnel` and Cloudflare reaches the box through a tunnel the box opens, instead of at its
address:

```json
"edge": { "cloudflare": { "tunnel": true } }
```

In TypeScript, `edge: cloudflare({ tunnel: true })`.

- The Cloudflare token also needs **Account · Cloudflare Tunnel · Edit**.
- It works whatever fronts the box, with no origin certificates, and requests that reach the
  box's address for a tunneled hostname are refused.
- One `ocel-tunnel` container (`cloudflared`, pinned, updates off) serves every project on the
  box that sets `tunnel`.

### Caching at Cloudflare

Set `cache` and the project's Cloudflare worker serves the box's apps, as it serves a function
on another provider:

```json
"edge": { "cloudflare": { "cache": true } }
```

In TypeScript, `edge: cloudflare({ cache: true })`; it works with `tunnel` too. A Next app with no
Dockerfile is then built by ocel's Next adapter, as a serverless Next app is, and routed, cached
and purged at Cloudflare, middleware and the edge runtime included; `image.command` and
`image.context` are refused on it. Its container runs Next's own cache, and in an app that
revalidates keeps none of it on its disk, so every start, a rollback included, begins empty: the
worker keeps the pages. What the worker keeps of any other app is in
[caching container apps](/docs/providers/cloudflare#caching-container-apps).

- The Cloudflare token also needs **Workers Scripts · Edit**, **Workers Routes · Edit** and
  **Workers R2 Storage · Edit**.
- The first deploy that sets it installs the tier's releases store and an R2 bucket for the files
  the worker serves; the box keeps the credential that writes them, sealed. A deploy by another
  version of ocel installs that version's releases store; `ocel bootstrap` installs none on a box.
- A Next app built from your own Dockerfile is kept by its own cache headers, as any other app
  is, and a revalidation inside it purges nothing at Cloudflare.
- A revalidation in a Next app ocel's adapter built purges the worker's copy of what it names, on
  every release of the app the box keeps.
- `/_next/image` is optimized by the box from the build's own files, and kept by the worker.
- Turning `cache` on or off is a deploy: the box keeps serving while the next one moves the
  project's hosts. A rollback to a promotion deployed before the change is refused.

## Behind your own proxy

If the box already runs a proxy on ports 80 and 443, name it with `proxy` and ocel runs no
`ocel-proxy`:

```json
"provider": { "vps": { "ssh": "prod", "proxy": "manual" } }
```

| | Ocel's own | `manual` | `traefik` | `caddy` |
| --- | --- | --- | --- | --- |
| Routes each hostname to ocel | ocel | you | ocel writes `ocel.yml` | ocel writes `ocel.caddy` |
| Issues certificates | ocel, over http-01 | your proxy | your Traefik, through `resolver` | your Caddy |
| Preview hostnames | every one under the base | once you route `*.<base>` | each claimed one | each claimed one |

Every project on a box must name the same `proxy`; a deploy that doesn't is refused with the
value to write. `certificates` can't be set beside `proxy`.

### The `proxy` option

```json
"proxy": "manual"
"proxy": { "traefik": { "preset": "coolify" } }
"proxy": { "traefik": { "directory": "/etc/traefik/dynamic", "resolver": "letsencrypt" } }
"proxy": { "caddy": { "directory": "/etc/caddy/ocel.d", "container": "caddy" } }
```

| Field | On | Meaning | Default |
| --- | --- | --- | --- |
| `preset` | `traefik`: `coolify`, `dokploy`; `caddy`: `coolify` | Fills every other field. A field written beside it overrides. | |
| `directory` | `traefik`, `caddy` | Where your proxy reads ocel's file from. | Required without `preset` |
| `containerDirectory` | `traefik`, `caddy` | Where `directory` is mounted inside the proxy's container. | `directory` |
| `resolver` | `traefik` | The `certResolver` ocel's routers name. | Required without `preset` |
| `previewResolver` | `traefik` | A DNS-01 resolver for one `*.<preview base>` wildcard. | One certificate per preview hostname |
| `entrypoints.https` / `.http` | `traefik` | Entry points ocel's routers and redirects attach to. | `websecure` / `web` |
| `container` | `caddy` | The container Caddy runs in. | Caddy runs as `caddy.service` |
| `config` | `caddy` | The file `caddy reload --config` names in `container`. | `/etc/caddy/Caddyfile` |
| `network` | all | A docker network the switchboard joins, so the proxy reaches it by name. | |
| `port` | all | The loopback port the switchboard is published on. | `8480` |

`network` and `port` are exclusive on `traefik` and `caddy`; on `manual`, `port` is always
published and `network` joined too. The presets fill in:

| | `traefik` + `coolify` | `traefik` + `dokploy` | `caddy` + `coolify` |
| --- | --- | --- | --- |
| `directory` | `/data/coolify/proxy/dynamic` | `/etc/dokploy/traefik/dynamic` | `/data/coolify/proxy/caddy/dynamic` |
| `containerDirectory` | `/traefik/dynamic` | | `/dynamic` |
| `resolver` | `letsencrypt` | `letsencrypt` | |
| `entrypoints` | `http` / `https` | `web` / `websecure` | |
| `network` | `coolify` | `dokploy-network` | `coolify` |
| `container` | | | `coolify-proxy` |
| `config` | | | `/config/caddy/Caddyfile.autosave` |

### Behind nginx or any proxy (`manual`)

Ocel never writes to your proxy. `ocel domain add` prints each route, then waits until the
hostname answers through ocel on `127.0.0.1:443`:

```
Route shop.example.com → http://127.0.0.1:8480 (keep Host, set X-Forwarded-Proto)
```

A catch-all works too:

```nginx
client_max_body_size 0;

location / {
    proxy_pass http://127.0.0.1:8480;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

A proxy in a container can't reach the host's loopback: name its docker network (it must
exist at bootstrap) and forward to `http://ocel-switchboard:8080`.

```json
"proxy": { "manual": { "network": "web" } }
```

Apps trust `X-Forwarded-Proto` and `X-Forwarded-Host` only from the loopback port and that
network, so put only trusted containers on it. `X-Forwarded-For` is never passed; apps see your
proxy as the client.

### Behind your Traefik

Ocel writes `ocel.yml` into the directory your Traefik's file provider watches: an https router
per hostname naming `resolver`, plus an http redirect, at priority 1000000 and with no catch-all.

- Traefik reaches the switchboard at `http://ocel-switchboard:8443` on `network`, or on
  `127.0.0.1:<port>` only from the host network.
- Ocel refuses a hostname one of your routers (files or container labels) already matches.
  Consul, Kubernetes and other providers aren't checked.
- Traefik never deletes a certificate from `acme.json`. If it fails to get one (usually DNS),
  it retries only on its next config change: fix DNS, then restart Traefik.
- Traefik turns `;` in a query into `&` unless each entry point sets
  `http.encodeQuerySemicolons: true`.
- Behind Cloudflare, rotate the box's client certificate before it expires (ten years from
  when it was minted).

### Behind your Caddy

Import ocel's directory in your Caddyfile once, and name it:

```txt title="/etc/caddy/Caddyfile"
import /etc/caddy/ocel.d/*.caddy
```

```json
"proxy": { "caddy": { "directory": "/etc/caddy/ocel.d" } }
```

Coolify's Caddy already imports `/dynamic/*.caddy`, so the `coolify` preset needs no line.

- Ocel reloads Caddy only when `ocel.caddy` changes, never on a release. A refused reload puts
  the old file back and shows Caddy's error. A reload can drop about one request under load;
  under `caddy.service` it also closes WebSockets.
- `caddy.service` reloads through `/etc/sudoers.d/ocel-caddy-reload`, and needs `curl` on the
  box. A containerised Caddy with no `network` needs `network_mode: host`.
- The admin endpoint must be on.
- Ocel refuses a hostname your Caddy already serves, and never writes your Caddyfile.
- Behind Cloudflare, give the directory to Caddy's group (`chgrp caddy /etc/caddy/ocel.d`).

### Moving a box to another proxy

Change `proxy` and run `ocel bootstrap <tier>`. Its plan shows what changes, how many
hostnames need new certificates (Let's Encrypt allows 50 per registered domain per week), and
the downtime. Ocel never stops or starts a proxy it doesn't run:

| From → to | You |
| --- | --- |
| Ocel's own → yours | Start your proxy when told. Bootstrap waits up to 10 minutes for every hostname. |
| Yours → ocel's own | Stop your proxy first. |
| Same proxy, new `directory` or `resolver` | Nothing; no downtime. |
| Same proxy, new `network` or `port` | With `manual`, forward where bootstrap prints. |

Deploys are refused until the move finishes. If it stops, fix what it names and run bootstrap
again.

## Health checks

A deploy switches traffic to a new container only once it answers 2xx on its health path. Set
it with [`health.path`](/docs/configuration#health) in the app's `compute.container`.

Without one, the first deploy asks for `/up`, `/health`, `/healthz`, then `/`. The first that
doesn't answer 404 or 405 becomes the health path, even if it answers an error, and later deploys
keep it:

```
api answers its health check on /health (found by probing /up, /health)
```

If every path answers 404 or 405, the deploy fails and asks you to set `health.path`.

## Images

With no `registry`, each deploy sends the app's whole image to the box over SSH, and warns when
that is slow or large. Name a registry and the box pulls by digest, moving only changed layers:

```json
"registry": { "server": "ghcr.io/acme", "username": "acme-bot", "password": "${REGISTRY_TOKEN}" }
```

`password` names an environment variable ([Configuration](/docs/configuration)). The box logs
out after each pull.

## Resources on the box

Each runs in a container on the project's own network, publishes no port, and gets a password
generated on the first deploy and sealed on the box. A [transform](/docs/transforms#on-a-vps)
changes the image, arguments, memory or volume.

| Resource | Runs as | Notes |
| --- | --- | --- |
| `postgres` | One Postgres container, data on a docker volume | A newer major `version` dumps, starts the new version on a fresh volume and restores, with the database down meanwhile. On failure the old version starts again. |
| `kv` | One Valkey container per store | A crash loses about the last second of writes. Apps connect as `ocel`. 8 → 9 works; 9 → 8 fails. |
| Topics, tasks | One Postgres with pgmq for the environment; each worker in its own container, from its app's image | Workers have no `maxDuration` ceiling. Python workers are refused at build. |
| Realtime | The Ocel gateway in a container | See [Realtime](/docs/sdk/realtime). |
| `bucket` | A store the box keeps for the project, or one you bind | See [Bucket](/docs/sdk/bucket#on-a-vps). |

A resource whose settings change is stopped gracefully (60 s) and renamed aside, then its
successor is started and checked. If the successor fails, the old one is put back.

Bootstrap warns when `vm.overcommit_memory` isn't `1` or transparent huge pages are `always`:
Valkey's background save can fail without overcommit.

### Container limits

Every container Ocel runs has a memory limit. An app, worker or resource container's is drawn
from the box's size, as `docker info` reports it (`MemTotal`, `NCPU`):

| Container | Memory | CPUs |
| --- | --- | --- |
| Production app, worker or resource | Half the box's | No cap |
| Preview app, worker or resource | A quarter of the box's | Half the box's |
| `kv` store | Twice its `maxmemory`, plus 64 MiB | |
| Realtime gateway | 256 MiB; refuses sockets past 4096 | |
| `ocel-switchboard` | 256 MiB | |
| `ocel-proxy` (Caddy) | 512 MiB | |
| `ocel-tunnel` | 256 MiB | |

No limit is below 256 MiB. A [transform](/docs/transforms#on-a-vps)'s `memory` or `cpus` on a
resource container replaces the default. Apps and workers have no setting of their own yet.

### Backups

Each postgres, kv store and bucket store the box keeps is copied once a day while it runs
(`ocel-backups.timer`, delayed at random by up to an hour), under
`/var/lib/ocel/<tier>/backups/<container>/`:

| Kind | Copied with | Kept |
| --- | --- | --- |
| `postgres` | `pg_dump` | The newest seven dumps |
| `kv` | Valkey's own `dump.rdb` | The newest seven dumps |
| Bucket store | `rclone sync --backup-dir`, object by object; the rclone image is pinned by digest | One mirror in `current/`, plus, for the last seven copies, the objects each one overwrote or deleted |

Before a run, the sweep checks there is room for twice the last dump. One copy that fails does
not skip the others. Backups sit on the box's own disk: copy them off the box if losing it must
not lose the data.

On the box (`docker ps --filter label=ocel.backup` names the containers):

```bash
sudo /usr/local/lib/ocel/backups <tier> dump <container>
sudo /usr/local/lib/ocel/backups <tier> restore <container> [<backup>]
```

`restore` takes the newest backup when it names none, and works for every kind. A kv store is
restored as the base of a fresh AOF; a bucket store from a read-only mount.

`ocel projects destroy` removes each resource with its volume, password and backups.

## Logs and caching

Containers log with Docker's `local` driver, at most 100 MiB each. Read them with
[`ocel logs`](/docs/cli/logs).

Nothing ocel runs on the box caches responses. Unless [Cloudflare caches](#caching-at-cloudflare)
in front of it, a Next app runs as a plain Next server under `next start`, built by Railpack or
from a Dockerfile, the one `image.dockerfile` names or the one beside
the app, so Next's own cache inside the container is the only one, and a deploy that replaces the
container starts it over from what the build prerendered. Its build reads its public values:
Railpack's build step is handed them, and a Dockerfile reads them as build arguments; see
[Environment variables](/docs/frameworks/nextjs#environment-variables).

## Upgrades

After upgrading ocel, a deploy that needs a newer box agent tells you to run `ocel bootstrap
<tier>`. Docker upgrades are yours.

Bootstrap sets `"live-restore": true` in `/etc/docker/daemon.json`, checked with
`dockerd --validate` and applied with `systemctl reload docker`, so a daemon restart or upgrade
stops no container. It leaves the setting alone when the file already sets `live-restore`, or
the box is in a swarm.

## Errors

| You see | Fix |
| --- | --- |
| `… is neither root nor has passwordless sudo` | Grant the login passwordless sudo, or connect as root. |
| `… is missing <tools>` | Install them. |
| `the host key for … is in none of …` | Check the fingerprint against the machine, then accept, or in CI run the `ssh-keyscan` line it prints. |
| `the host key for … changed` | If the machine was rebuilt, run the `ssh-keygen -R` line it prints. |
| `docker … is older than 28.0`, `… is the snap package`, `… runs rootless` | Install Docker 28.0 or later from Docker's own packages as the system daemon, then bootstrap. |
| Bootstrap names what holds port 80 or 443 | Stop it, or deploy [behind it](#behind-your-own-proxy). |
| `ports 80 and 443 on … are unreachable from this machine` | Allow inbound TCP 80 and 443 in your cloud firewall, or the box's own. |
| `… has … free on …; this deploy needs …` | Free space on Docker's data root. |
| `app … asks for instances.min …` | A box runs one container per app: set both to 1 or leave them off. |
| `… orders a publicly trusted certificate for each preview hostname …` | See [Previews](#previews). |
| `this box's agent … predates this ocel` | Run `ocel bootstrap <tier>`. |
| `no ocel-switchboard container on …` | Run `ocel bootstrap <tier>`. |
| A deploy refused with a `proxy` value to write | Every project on a box must name the same `proxy`. |
| `Sending …'s image to … took …` | Name a [`registry`](#images). |
| Every health path answered 404 or 405 | Set [`health.path`](#health-checks). |

`ocel doctor` checks DNS, ports, the proxy and the switchboard.

## Options

| Option | Meaning |
| --- | --- |
| `ssh` | The box: a `Host` alias, or `{ host, user, port, identityFile }`. |
| `deployKey` | Path to the public key `ocel-deploy` accepts. Default: the bootstrapping login's keys. |
| `certificates` | Certificate paths on the box, keyed by hostname. Not with `proxy`. |
| `proxy` | What fronts ports 80 and 443. Default: ocel's own. See [the `proxy` option](#the-proxy-option). |
| `perHostnamePreviewCertificates` | Deploy previews even though each preview hostname gets a public, logged certificate. See [Previews](#previews). |
| `edge`, `dns` | `cloudflare`. See [Behind Cloudflare](#behind-cloudflare). |
