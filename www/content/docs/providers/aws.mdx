```bash
ocel init --provider aws
```

```ts tab="TypeScript" tab-group="config" title="ocel.config.ts"
import { defineConfig } from "ocel/config";
import awsProvider from "ocel/providers/aws";

export default defineConfig({
  slug: "my-app",
  provider: awsProvider({ region: "eu-west-1" }),
  apps: [{ name: "web", path: "." }],
});
```

```json tab="JSON" title="ocel.json"
{
  "$schema": "https://ocel.dev/schema/ocel.schema.json",
  "slug": "my-app",
  "provider": { "aws": { "region": "eu-west-1" } },
  "apps": [{ "name": "web", "path": "." }]
}
```

Credentials come from the shell, the same ones `aws sts get-caller-identity` answers to.
`ocel permissions deploy` prints what they need as a list of managed policies, each a
`PolicyName` and `PolicyDocument` small enough for IAM to accept; attach every one to the role
or user that deploys.

```bash
ocel deploy
```

A first deploy in a terminal offers to run `ocel bootstrap production` when the account has no
Ocel infrastructure. A script or CI is never asked, so bootstrap there first:

```bash
ocel bootstrap production
ocel deploy
```

The bootstrap holds what every deploy needs: the state, artifact and asset buckets, the state and
variables tables, the app boundary, and the roles the tag invalidator and API Gateway run as. The
rest is added by the first deploy that needs it, with the deploy credential, and listed by
`ocel bootstrap status`:

| Part | Added by |
| --- | --- |
| `cloudfront` | the first deploy through CloudFront: the routes store, resolver and empty-body functions, cache and headers policies and asset access every distribution shares |
| `image-optimizer` | the first deploy of an app whose build optimizes images |
| `tag-invalidator` | the first deploy of an app that revalidates |
| `apigateway-preview` | the first `ocel domain use --preview` behind API Gateway: the REST API that answers 404 for a preview host no preview claims |
| `function-network` | the first deploy of a serverless app that uses a `postgres` or `kv` ocel provisions: the [private subnets and NAT gateway](#serverless-apps-and-the-vpc) its functions run in, about $36.50 a month idle. The last app out takes it down |

A dry deploy lists the parts it would add. `ocel bootstrap production` makes each recorded part
again, and `ocel bootstrap destroy production` removes them with the rest.
`ocel bootstrap production --remove <part>` takes one part down, whichever added it, and refuses
while a project here uses it unless you pass `--force`; the next deploy that needs a part a deploy
adds adds it back. `--force` never takes `containers` or `function-network` down while an app still
runs in it: remove those apps or destroy their environments, and the last one to leave takes it
down.

Two parts only the bootstrap credential may make, so no deploy adds them:

| Part | Wanted by |
| --- | --- |
| `variables-key` | the first command in a tier that seals a value: `ocel env set`, `ocel env ui`, or a deploy that registers a scheduled env source or reads live values. It is the KMS key values are sealed under, about $1 a month |
| `cloudflare-edge` | the first deploy through [Cloudflare](/docs/providers/cloudflare): the IAM user the edge signs its calls with, its access key, and the worker that keeps the tier's releases |

The command that wants one records that its project does, and stops. In a terminal Ocel offers to
add it there and then; a script or CI is refused with `ocel bootstrap production`, which adds every
part a project here was refused for. `ocel bootstrap status` shows such a part as wanted by those
projects until then. A `--dry` deploy records nothing.

**Scope image deletes to one project.** Untagged, the deploy user or role may delete container
images in every Ocel ECR repository of the account. Tag it `ocel:project` with the project's
slug as its repositories spell it (`ocel/<slug>.<app>`: lowercase, each run of other characters
a single `-`), and it may create, tag and delete images only in that project's repositories.

## Options

| Option | What it does |
| --- | --- |
| `region` | The region to deploy into, such as `us-east-1`: a region, never an availability zone such as `us-east-1a`. Omit it and ocel reads `AWS_REGION`, `AWS_DEFAULT_REGION`, then the profile. |
| `variablesKey` | ARN of a KMS key to encrypt this account's variables under. Omit it and `ocel bootstrap` makes a key ocel owns, once a project here first seals a value. |
| `certificates` | Already-issued ACM certificate ARNs, keyed by hostname. A hostname left off gets a certificate ocel requests, validates and deletes again. |
| `logs.liveTail` | Tail through CloudWatch Live Tail: lower latency and no gaps between polls, billed per session-minute past the free tier, at most 15 sessions per account. Off, `ocel logs --tail` polls `FilterLogEvents`. |
| `edge` | `cloudfront` (default), `api-gateway` or [`cloudflare`](/docs/providers/cloudflare). See [Edge](#edge). |
| `dns` | `route53` or [`cloudflare`](/docs/providers/cloudflare). A Cloudflare edge needs `cloudflare`. |

## Edge

`api-gateway` serves a preview on its alias only, with no hostname per deployment: each
hostname would take a REST API of its own, and a region holds at most 600.

### CloudFront origin shield

For a Next.js release with prerendered pages, `GET` and `HEAD` cache misses go through
[Origin Shield](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/origin-shield.html)
in the function's region, or the nearest that has it. An uncached page then reaches the function
as few as once, not once per edge location. Static files, containers and releases without
prerendered pages skip it.

It bills $0.0075 per 10,000 requests in the US, for every miss on a response cached under an
hour or not at all. To turn it off:

```ts tab="TypeScript" tab-group="config" title="ocel.config.ts"
import { defineConfig } from "ocel/config";
import awsProvider from "ocel/providers/aws";
import { cloudfront } from "ocel/providers/aws/edge";

export default defineConfig({
  slug: "my-app",
  provider: awsProvider({ edge: cloudfront({ originShield: false }) }),
  apps: [{ name: "web", path: "." }],
});
```

```json tab="JSON" title="ocel.json"
{
  "$schema": "https://ocel.dev/schema/ocel.schema.json",
  "slug": "my-app",
  "provider": { "aws": { "edge": { "cloudfront": { "originShield": false } } } },
  "apps": [{ "name": "web", "path": "." }]
}
```

## KV stores

`kv("cache")` is an ElastiCache Valkey replication group, cluster mode off: a primary and a
replica in another availability zone that takes over if the primary fails. Two
`cache.t4g.micro` nodes cost about $18.69 a month in us-east-1.

- **In the VPC.** The group sits in the default VPC's subnets and admits port 6379 from inside
  that VPC only. A container app runs there; a serverless app joins it through the
  [function network](#serverless-apps-and-the-vpc).
- **Auth.** TLS, encrypted at rest, and an AUTH token ocel generates, kept in SSM Parameter Store
  under `/<namespace>/kv/`.
- **`memory`** picks the cheapest node that holds it: `cache.t4g.micro` up to 256mb, then
  `t4g.small`, `t4g.medium`, `m7g.large`, `r7g.large`, `r7g.xlarge` and `r7g.2xlarge` up to
  32gb. A transform cannot set the node type.
- **`eviction`** left out means never evict, as on every provider (ElastiCache's own default
  is `volatile-lru`).
- **`version`** 8 runs ElastiCache 8.1, 9 runs 9.1. Moving 8 to 9 upgrades the group in place;
  ElastiCache cannot move back to an older major.
- **Snapshots.** One a day, kept a day, at no charge.

**One node.** A [transform](/docs/transforms) can halve the cost by dropping to a single node,
for an environment that can lose its data. ElastiCache runs neither failover nor Multi-AZ
without a replica, so turn both off; a deploy refuses a patch that leaves either on:

```ts title="transforms/kv.transform.ts"
import { defineTransform } from "@ocel/transforms";

export default defineTransform({
  aws: {
    kv: {
      replicationGroup: { numCacheClusters: 1, automaticFailoverEnabled: false, multiAzEnabled: false },
    },
  },
});
```

With no replica and no append-only file, a replaced node comes back empty.

`ocel destroy` takes the replication group, its snapshots, parameter and subnet groups,
security group and token.

## Serverless apps and the VPC

Aurora and ElastiCache answer inside the default VPC only, and a Lambda function runs outside
any VPC. A serverless app that uses a `postgres` or `kv` ocel provisions is attached to the VPC
with no transform: every function and worker of the app runs in the tier's `function-network`
part, and the app's role gets `AWSLambdaVPCAccessExecutionRole`. An app that uses neither, or
only a binding another project or your own infrastructure provisioned, stays outside the VPC.

A function in a VPC has no internet access of its own, so the part holds:

- **Two private subnets** in two availability zones, the first free `/20` blocks counting down
  from the top of the default VPC's address range, so they never overlap a subnet already there.
  A deploy refuses a VPC with no free block. No database, cache, cluster or load balancer is
  placed in them.
- **One NAT gateway** and its elastic IP, in a default subnet: about $32.85 a month (730 hours at
  $0.045), $3.65 for the public IPv4 address, and $0.045 per GB it processes, in us-east-1. One
  per tier, priced by `ocel cost scan` and `ocel bootstrap status`.
- **Gateway endpoints** for S3 and DynamoDB, at no charge, so ocel's own runtime traffic stays off
  the NAT gateway.
- **A security group** that lets functions call out and admits nothing.

The first deploy that attaches can take several minutes longer while Lambda builds its network
interfaces, and a dry deploy lists the part as a slow create. Lambda reclaims an attachment
idle for 14 days, and the next invocation waits for it to be rebuilt. The last app or worker to
leave takes the part down once its functions have left the subnets, which waits for Lambda to
release their interfaces. A takedown that fails leaves the part recorded with no user:
`ocel bootstrap production --remove function-network` finishes it.

To place a function in subnets of your own, set `vpcConfig` in a
[transform](/docs/transforms#placing-a-function-in-your-own-vpc). It takes the place of the
automatic attach for the functions it names.

## Topics, tasks and workers

| Declared | On AWS |
| --- | --- |
| task | an SQS queue of its own |
| topic | an SNS topic delivering to one SQS queue per consumer |
| `ordered` | FIFO queues, with `key` as the message group |
| `cron` | an EventBridge Scheduler schedule, invoking a Lambda worker or sending to a container worker's queue |
| worker | a Lambda function built from the app's code, with no URL; on container compute, an ECS service of its own running the app's image |

Every queue has a dead-letter queue; `deadLetter(consumer)` lists, redrives and purges failed
runs as on every provider. Runs, idempotency keys and debounce records live in the account's
state table. Queues, topics and schedules bill by the request.

Limits and differences:

- `maxDuration` is at most 15 minutes on a Lambda worker and 12 hours on container compute,
  the longest SQS keeps a received message hidden. A longer one is refused, naming the task
  and its file and line.
- A run that finds its worker at its concurrency waits on the queue, up to five minutes at a
  time. On a FIFO queue each wait is a delivery, and SQS dead-letters after 1,000, so a run
  still waiting then ends failed.
- A delayed `ordered` run holds up later runs with the same `key` until it is due.
- Lanes are recorded but don't change start order: SQS has no priority.
- Workers, Lambda or container, run the most recently deployed code. Rolling an app back
  changes its routes, not its workers; deploy again to change them.

`ocel destroy` takes the workers, queues, topics and schedules. Records expire on their own: a
run 30 days after it finishes or was due, an idempotency key an hour after its
`idempotencyKeyTTL` (30 days by default).

### Workers on container compute

A worker of a container app runs as an ECS service of its own in the tier's cluster, from the
app's image, with no load balancer and no port. It reads its queues itself and keeps each
message hidden until its run ends; retries, concurrency slots, abort, timeout and run records
work as on a Lambda worker. A consumer's `concurrency`, or its worker's, is how many messages
the service works at once, ten without one.

The service sits at no tasks and costs nothing then:

- A send to one of its queues starts a task: the sender reads the service and sets it to one
  task when it has none. A message not due for a minute or more does not wake it.
- If that wake fails, or the message came from somewhere that cannot make the call, an alarm
  on the visible messages of the worker's queues starts a task within a few minutes and adds
  one a minute while the backlog lasts, up to the app's `instances.max`. Each alarm watches at
  most nine queues and costs $0.10 a month per queue.
- A worker with nothing to work for five minutes and empty queues sets its service back to
  its floor.

A worker that joins the app named after it has that app to itself: the app deploys no web
service or load balancer rule, and its `instances.min` is the floor of its workers' services,
none unless it sets one. A worker that joins an app that serves traffic sits at no tasks
whatever that app's `instances.min`, which stays the floor of the app's own service. So no
worker is billed while idle unless its app asks for it.

A run working when its task stops, for a deploy or a scale-in, is queued again and the next
task starts it. A task renews its hold on each run it works every 40 seconds, so a run whose
task crashes is started again by the next task within about three minutes. A `cron` task on
a container worker has its schedule send a message to the task's queue, which wakes the
worker like any backlog, and the worker starts the run once for each minute the schedule
fires.

A container app's workers count as a user of the `containers` part, so the cluster stays while
their services exist. Moving an app between serverless and container compute starts its workers
on the new compute and takes the old ones down once the promotion serves.

## Logs

Each Lambda function and worker logs to a CloudWatch log group of its own, deleted with it by
`ocel destroy`. Containers log to `/ocel/containers/<tier>`, one group per tier. Both keep 14
days. Read them with [`ocel logs`](/docs/cli/logs), which lists the CloudWatch rate limits a read
shares.
