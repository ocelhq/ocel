Declare a resource once in a [discovery folder](/docs/configuration#discoverypaths), then import it wherever you use it. The declaration is the provisioning step.

```ts title="resources/index.ts"
import { postgres } from "ocel/postgres";

export const db = postgres("main");
```

```ts title="src/server.ts"
import express from "express";
import { db } from "../resources";

const app = express();

app.get("/documents", async (_req, res) => {
  const { rows } = await db.query("select * from documents");
  res.json(rows);
});

app.listen(3000);
```

## How it works

`ocel dev`, `ocel deploy` and `ocel preview` run only your discovery folders, never your app. Each declaration reports itself to the CLI, which provisions the resources (in containers under `ocel dev`, in your account on deploy), then starts or ships the app with their bindings. This pass is **discovery**.

```bash
ocel dev / deploy / preview    starts a local RPC server
  └─ runs the discovery folders
       └─ postgres("main")  →  Declare { postgres "main" }
  └─ provisions what was declared
  └─ starts or ships the app with the bindings
```

The CLI reads a folder's language from its source files:

| Language | Install | Discovery runs |
| --- | --- | --- |
| TypeScript | [`ocel`](https://www.npmjs.com/package/ocel) | the folder's files |
| Go | [`ocel.dev`](https://pkg.go.dev/ocel.dev) | a generated `main` that imports the folder's package, with `go run` under the `.ocel/` of the nearest `go.mod` at or above the folder, up to the project root. Your `main` and `go.work` are untouched. |
| Python | [`ocel`](https://pypi.org/project/ocel/) | the folder imported as a package from the nearest `pyproject.toml` or `requirements.txt`, using the project's `.venv` when present. The folder ships with the app, so `from resources import db` resolves once deployed. |
| Rust | [`ocel-sdk`](https://crates.io/crates/ocel-sdk) | your own binary (`cargo run --bin` of the binary the app's `entrypoint` names, or else of the one the crate runs by default). No discovery folder: see below. |

Rust declares from the app crate. Derive `ocel::Resources` on a struct of resources and `ocel::Env` on a struct of variables, put `#[ocel::main]` on `main`, and read them with `Infra::load()?` and `Env::load()?`. During discovery `#[ocel::main]` reports what the binary links and returns before your `main` body runs.

## Gotchas

### Define, don't read

Discovery runs before anything exists. Declare in the discovery folder; read everywhere else.

```ts title="resources/index.ts"
export const db = postgres("main");

console.log(db.connectionString); // fails: not provisioned yet
```

```ts title="src/server.ts"
import { db } from "../resources";

console.log(db.connectionString); // fine
```

### An app binds what it imports

On deploy, an app is bound only to the resources declared in files it imports. A resource no app imports is provisioned but bound to nothing, and reaching it fails with a missing binding error.

An app that imports a project file through a dynamic `import()` or `require()` with a computed path is refused, since its resources cannot be resolved.
