---
title: Realtime
description: Typed channels that browsers subscribe to and your server publishes on.
---

A realtime resource holds a set of channel patterns. Your app decides who may subscribe or
publish, in rules it runs behind its own realtime handler. The transport that holds the
sockets only checks the short-lived tokens your handler signed.

```ts title="resources/realtime.ts"
import { realtime } from "ocel/realtime";

export const rt = realtime("app", {
  authorize: async (req) => {
    const session = await auth.api.getSession({ headers: req.headers });
    return session ? { id: session.user.id } : null;
  },
  channels: {
    "orders/:orderId": {
      schema: OrderEvent,
      subscribe: async ({ auth, params }) => ownsOrder(auth.id, params.orderId),
    },
    status: { schema: Status, subscribe: "public" },
  },
});

await rt.publish("orders/:orderId", { params: { orderId }, body: { status: "shipped" } });
```

## Where it runs

| Target | Transport | A subscription outlives a revoked caller for at most |
| --- | --- | --- |
| `ocel dev` | the Ocel gateway inside `ocel dev` | the dev server's lifetime |
| AWS | AppSync Events | 24 hours |
| Google Cloud | the Ocel gateway on Cloud Run | 60 minutes |
| VPS | the Ocel gateway in a container on the box | the next deploy |

Access is checked when a browser subscribes and again every time it reconnects. A
subscription that is already open keeps receiving events until its connection ends, so
taking a user's access away takes effect within the window above, not at once.

## On AWS

Each environment gets one AppSync Event API, and each realtime resource is a channel
namespace on it. Ocel deploys one Lambda authorizer per API: a Go function with 128 MB on
arm64 that checks each connect and subscribe token against the resource's public key. It
runs none of your code. It answers every request uncached, so a token is never admitted
after it expires.

- **Publishing.** Only the server publishes to AppSync. `publish` hands the event to the
  Ocel runtime beside your app, which signs a `POST /event` with your app's own IAM role.
  That role may connect to its API and publish to its own namespace and nothing else. A
  browser publish goes through your handler, which runs the `publish` rule and then
  publishes from the server.
- **Signing key.** The first deploy mints an Ed25519 key per resource and keeps it in
  Secrets Manager. It reaches your app through the resource's binding. Removing the
  resource, or destroying the environment, deletes the key at once with no recovery
  window.
- **Connection lifetime.** AppSync closes every connection after 24 hours. The browser
  client reconnects on its own and asks your handler to authorize every live
  subscription again in one request, so your rules run again.
- **Cost.** AppSync bills each publish, subscribe and delivered message as an operation,
  plus connection minutes. The authorizer is billed per connect and subscribe, and each
  signing key is one secret. Ocel's cost estimate prices all of these.

Realtime needs AppSync and Secrets Manager permissions on the deploy credentials and on
the boundary every app role is made under. Both live in the bootstrap stack, so an account
bootstrapped before realtime existed has its bootstrap stack updated before its first
realtime deploy.

## On Google Cloud

Each environment gets one Cloud Run service running the Ocel gateway, and it serves every
realtime resource in that environment. Browsers connect to its `run.app` address directly,
so it takes traffic from anywhere with Cloud Run's invoker check off. The gateway admits a
socket from any origin; the tokens your handler signs are the only check.

- **Publishing.** `publish` hands the event to the Ocel runtime beside your app, which
  posts it to the gateway's `/publish` under a token signed with the resource's key. The
  runtime sends a publish again only when Cloud Run answered 429 or the request never
  left, so an event is delivered at most once.
- **Keys.** The first deploy mints an Ed25519 key per resource and keeps it in Secret
  Manager. It reaches your app through the resource's binding. The gateway reads every
  resource's public key from one secret per environment, mounted at its latest version, so
  adding or removing a resource changes no revision. The gateway reads that secret again
  at least every 30 seconds.
- **Connection lifetime.** Cloud Run ends a request after 60 minutes, and a socket is a
  request. The browser client reconnects on its own and asks your handler to authorize
  every live subscription again.
- **Capacity.** The gateway runs as one instance of 1 vCPU and 1 GiB, and holds up to 950
  sockets. It refuses the next one with 503 before it opens, keeping room for publishes,
  and the client retries.
- **Upgrades.** A deploy that brings a new gateway version rolls a new revision. Sockets
  on the old revision stay open for up to 60 minutes but stop receiving events, because
  publishes reach the new one. While the new revision starts, Cloud Run may also run a
  second instance for a short time, and sockets on it miss events from the other. Clients
  recover when those sockets close and reconnect.
- **Cost.** Cloud Run bills the gateway for every second a socket is open, at its
  request-based rate: about $70 a month if a browser is connected all the time, plus
  requests and egress. Each key is one secret. Ocel's cost estimate prices all of these.

The deploy credentials need Secret Manager admin, and the bootstrap adds the service
account the gateway runs as. Run the bootstrap again before the first realtime deploy in a
project bootstrapped before realtime existed.
