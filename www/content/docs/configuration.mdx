Every option lives in one config at the root of your project. `ocel init` writes
`ocel.config.ts` in a node project and `ocel.json` in any other.

```ts tab="TypeScript" tab-group="config" title="ocel.config.ts"
import { defineConfig } from "ocel/config";
import awsProvider from "ocel/providers/aws";

export default defineConfig({
  slug: "my-app",
  provider: awsProvider(),
  apps: [{ name: "web", path: "." }],
});
```

```json tab="JSON" title="ocel.json"
{
  "$schema": "https://ocel.dev/schema/ocel.schema.json",
  "slug": "my-app",
  "provider": "aws",
  "apps": [{ "name": "web", "path": "." }]
}
```

| Key | Required | Means |
| --- | --- | --- |
| `slug` | Yes | The project's identity in your provider account. Every stack and resource is keyed on it, so changing it starts a new project. |
| [`provider`](#provider) | | Where `ocel deploy` provisions, with its [edge](#edge) and [DNS](#dns). |
| [`apps`](#apps) | | The apps to deploy. Left off, ocel detects one at the project root. |
| `domains` | | `production`: the hostname or hostnames production serves. `preview`: the wildcard previews are served under, such as `*.preview.example.com`. See [Environments](/docs/environments). |
| [`discovery`](#discoverypaths) | | Where resource declarations are found. |
| [`bindings`](#bindings) | | Resources to bind to instead of provisioning. |
| [`envSource`](/docs/env-sources) | | Where each tier's values are read from. |
| [`lifecycle`](#lifecycle) | | Commands a deploy runs on your machine. |
| [`transforms`](/docs/transforms) | | A module path, or a list of them, that patches what ocel provisions. |
| [`registry`](#registry) | | Where container images are pushed. |
| `allowDegraded` | | Needs a deploy may go without rather than be refused over: `edge-middleware`, `edge-runtime`, `ppr-resume`, `edge-cache`, `streaming`. See [Cloudflare](/docs/providers/cloudflare). |

A directory holding two configs (two of `ocel.config.ts`, `ocel.json`, `ocel.yaml`,
`ocel.yml`, or two forms of one target such as `ocel.vps.config.ts` and `ocel.vps.json`)
is refused.

## TypeScript

`ocel.config.ts` compiles to the same document as `ocel.json`; every field, default and error
is the same.

| Import | From |
| --- | --- |
| `defineConfig`, `buildEnv` | `ocel/config` |
| A provider | `ocel/providers/<name>` |
| A provider's own edge or DNS, such as `cloudfront` | `ocel/providers/<name>/edge`, `ocel/providers/<name>/dns` |
| The Cloudflare edge and DNS | `ocel/edge`, `ocel/dns` |
| `infisical`, `exec` | `ocel/env-source` |

Descriptors take options as arguments, so your editor completes them:
`awsProvider({ edge: cloudfront() })`. Every command that reads the config runs the file
first, so each machine and CI job needs `node` on `PATH` and the `ocel` package. That is why
a go, rust or python project gets `ocel.json`.

`buildEnv` checks the variables the config itself reads, from the shell or a `.env` beside
it, against your schema before anything is provisioned:

```ts title="ocel.config.ts"
import { buildEnv, defineConfig } from "ocel/config";
import vpsProvider from "ocel/providers/vps";
import { z } from "zod";

const ssh = buildEnv({
  DEPLOY_HOST: z.string().min(1),
  DEPLOY_PORT: z.coerce.number().default(22),
});

export default defineConfig({
  slug: "my-app",
  provider: vpsProvider({ ssh: { host: ssh.DEPLOY_HOST, port: ssh.DEPLOY_PORT } }),
  apps: [{ name: "web", path: "." }],
});
```

## JSON

`ocel.json` needs no node. `ocel init --format json` writes it in a node project too.

- `$schema` is what your editor completes and validates against. It always describes the
  latest release.
- A key your CLI does not know is refused, with an error naming it.
- Comments and trailing commas are allowed.

## YAML

`ocel.yaml` or `ocel.yml` holds the same document. `ocel init --format yaml` writes it.

```yaml title="ocel.yaml"
# yaml-language-server: $schema=https://ocel.dev/schema/ocel.schema.json
slug: my-app
provider: aws
apps:
  - name: web
    path: .
```

The first line gives your editor the schema. Anchors and merge keys expand before ocel reads
the file, so apps can share settings.

## Variables

Any string may read an environment variable with `${NAME}`, from your shell or a `.env`
beside the config. An unset name refuses the deploy. Write `$${` for a literal `${`.

```ts tab="TypeScript" tab-group="config" title="ocel.config.ts"
import { defineConfig } from "ocel/config";
import vpsProvider from "ocel/providers/vps";

export default defineConfig({
  slug: "my-app",
  provider: vpsProvider({ ssh: { host: "${DEPLOY_HOST}", user: "deploy" } }),
});
```

```json tab="JSON" title="ocel.json"
{
  "$schema": "https://ocel.dev/schema/ocel.schema.json",
  "slug": "my-app",
  "provider": {
    "vps": { "ssh": { "host": "${DEPLOY_HOST}", "user": "deploy" } }
  }
}
```

`${NAME}` is for values that differ per machine, and is read unchecked, as a string. Secrets
belong in [variables](/docs/environments), stored in your own account.

### registry

Where container images are pushed. Its password is the one secret the CLI itself reads.

```ts tab="TypeScript" tab-group="config" title="ocel.config.ts"
import { defineConfig } from "ocel/config";

export default defineConfig({
  slug: "my-app",
  registry: { server: "ghcr.io/acme", password: "${REGISTRY_TOKEN}" },
});
```

```json tab="JSON" title="ocel.json"
{
  "$schema": "https://ocel.dev/schema/ocel.schema.json",
  "slug": "my-app",
  "registry": { "server": "ghcr.io/acme", "password": "${REGISTRY_TOKEN}" }
}
```

| Field | Required | Means |
| --- | --- | --- |
| `server` | Yes | The registry host and namespace, such as `ghcr.io/acme`. No scheme, no credentials. |
| `password` | Yes | `${NAME}` alone, read from your shell, then the project's `.env`, when the push authenticates. The secret itself, a bare `NAME`, text around the placeholder, or a `buildEnv` value is refused. |
| `username` | | The username to push as, where the registry wants one. |

## ocel.lock

`ocel lock` writes `ocel.lock` beside the config: the CLI's version and the sha256 of every
provider archive of that release. Commit it, so every machine and CI run fetches the same
bytes.

- A CLI of another version is refused until you run `ocel lock` again.
- With no `ocel.lock`, the first command that fetches providers writes one.
- `--dry` writes none. It pins the providers for that run alone.

## provider

```ts tab="TypeScript" tab-group="config" title="ocel.config.ts"
import { defineConfig } from "ocel/config";
import awsProvider from "ocel/providers/aws";
import { route53 } from "ocel/providers/aws/dns";
import { cloudfront } from "ocel/providers/aws/edge";

export default defineConfig({
  slug: "my-app",
  provider: awsProvider({ edge: cloudfront(), dns: route53({ zone: "example.com" }) }),
  apps: [{ name: "web", path: ".", domains: { production: "shop.example.com" } }],
});
```

```json tab="JSON" title="ocel.json"
{
  "$schema": "https://ocel.dev/schema/ocel.schema.json",
  "slug": "my-app",
  "provider": {
    "aws": { "edge": "cloudfront", "dns": { "route53": { "zone": "example.com" } } }
  },
  "apps": [{ "name": "web", "path": ".", "domains": { "production": "shop.example.com" } }]
}
```

In `ocel.json` a provider, edge, DNS or compute is an object keyed by its name with its
options as the value, or the name alone when it needs no options. Each provider's own options
are on its page: [AWS](/docs/providers/aws), [Google Cloud](/docs/providers/gcp),
[VPS](/docs/providers/vps).

### edge

What serves the project's hostnames in front of the origin. Naming an edge the provider does
not take is refused when the config is read.

| Provider | Edges | Left off |
| --- | --- | --- |
| AWS | `cloudfront`, `api-gateway`, [`cloudflare`](/docs/providers/cloudflare) | `cloudfront` |
| Google Cloud | `alb`, [`cloudflare`](/docs/providers/cloudflare) | No edge: each service answers on its Cloud Run URL |
| VPS | [`cloudflare`](/docs/providers/cloudflare) | No edge |

| Edge | Options |
| --- | --- |
| `cloudfront` | `originShield`: on unless `false`. See [AWS](/docs/providers/aws). |
| `cloudflare` | `tunnel`, `originDomain`. See [Cloudflare](/docs/providers/cloudflare). |
| `api-gateway`, `alb` | None. |

### dns

Where hostname records are written. Left off, the origin provider's own DNS.

| Provider | DNS |
| --- | --- |
| AWS | `route53`, [`cloudflare`](/docs/providers/cloudflare) |
| Google Cloud | [`cloudflare`](/docs/providers/cloudflare) |
| VPS | [`cloudflare`](/docs/providers/cloudflare) |

Each takes a `zone`. Left off, ocel picks the zone that covers the hostname.

## apps

| Field | Required | Means |
| --- | --- | --- |
| `name` | Yes | A DNS label. It labels every resource the app deploys and its preview hostname. |
| `path` | Yes | The app's directory, relative to the config. |
| [`compute`](#compute) | | `serverless` or `container`. Left off, the first compute the provider runs. |
| `arch` | | `x86_64` or `arm64`. Left off, what the provider runs the app on. A provider that cannot run the one named refuses the deploy before building. |
| `buildWithResources` | | Default `true`: a Next app's build reaches its deployed resources, so prerendered pages read them. `false` builds as if none were provisioned. |
| `domains` | | `production`: the hostname or hostnames this app serves in production. |
| `folder` | | The variables folder this app reads, when not the project's own. |

A provider that forwards no ports and serves no binding proxy builds without resources, and
the deploy says so.

### compute

`serverless` packs functions per route that scale themselves. `container` runs one image
serving every route. Name it alone, or key it with its options:

```ts tab="TypeScript" tab-group="config" title="ocel.config.ts"
import { defineConfig } from "ocel/config";

export default defineConfig({
  slug: "my-app",
  apps: [
    { name: "web", path: "web", compute: "serverless" },
    {
      name: "api",
      path: "api",
      compute: {
        container: {
          image: { dockerfile: "Dockerfile.prod", context: "." },
          health: { path: "/health" },
          instances: { min: 2, max: 10 },
        },
      },
    },
  ],
});
```

```json tab="JSON" title="ocel.json"
{
  "$schema": "https://ocel.dev/schema/ocel.schema.json",
  "slug": "my-app",
  "apps": [
    { "name": "web", "path": "web", "compute": "serverless" },
    {
      "name": "api",
      "path": "api",
      "compute": {
        "container": {
          "image": { "dockerfile": "Dockerfile.prod", "context": "." },
          "health": { "path": "/health" },
          "instances": { "min": 2, "max": 10 }
        }
      }
    }
  ]
}
```

A container option on a serverless app, or the reverse, is refused when the config is read.

### serverless

```ts tab="TypeScript" tab-group="config" title="ocel.config.ts"
import { defineConfig } from "ocel/config";

export default defineConfig({
  slug: "my-app",
  apps: [
    {
      name: "web",
      path: ".",
      arch: "arm64",
      compute: { serverless: { framework: "go", entrypoint: "./cmd/web" } },
    },
  ],
});
```

```json tab="JSON" title="ocel.json"
{
  "$schema": "https://ocel.dev/schema/ocel.schema.json",
  "slug": "my-app",
  "apps": [
    {
      "name": "web",
      "path": ".",
      "arch": "arm64",
      "compute": { "serverless": { "framework": "go", "entrypoint": "./cmd/web" } }
    }
  ]
}
```

| Field | Means |
| --- | --- |
| `framework` | `node`, `next`, `sveltekit`, `go`, `python` or `rust`. Left off, read from the app's directory (below). |
| `entrypoint` | The file a node app is served from, or the directory of a go app's main package, when it is not where ocel looks. |

With no `framework`, ocel reads the app's directory, in this order:

| Found | Framework |
| --- | --- |
| `go.mod` | `go` |
| `pyproject.toml` or `requirements.txt` | `python` |
| `package.json` naming `next`, or a `next.config.js`, `.mjs` or `.ts` | `next` |
| `package.json` naming `@sveltejs/kit` | `sveltekit` |
| `package.json` | `node` |
| `Cargo.toml` | `rust` |

A `Cargo.toml` beside a node or python manifest is that app's native extension, not a rust app.

A rust app builds as a static musl binary for its `arch`, so install the target:

```bash
rustup target add x86_64-unknown-linux-musl   # or aarch64-unknown-linux-musl
```

A crate that compiles C (`ring`, `aws-lc-rs`, `openssl-sys`) also needs a musl C cross
toolchain, most of all for `arm64` on an x86_64 machine: set `CC_aarch64_unknown_linux_musl`
and a linker, below or in `CARGO_TARGET_AARCH64_UNKNOWN_LINUX_MUSL_LINKER`. With neither,
ocel links with `rust-lld`.

```toml title=".cargo/config.toml"
[target.aarch64-unknown-linux-musl]
linker = "aarch64-linux-musl-gcc"
```

### container

Fields as in the [compute](#compute) example. A container takes no `framework`: ocel detects
a Next app and builds any other as its image describes.

| Field | Means |
| --- | --- |
| `image.dockerfile` | The Dockerfile, relative to the app's directory. Left off, the app's `Dockerfile`, or none. |
| `image.context` | The build directory, relative to the project. Left off, the workspace root the app belongs to. |
| `image.command` | The command that builds the app inside the image. Left off, the app's build script. |
| [`health.path`](#health) | The path checked before a release serves traffic. |
| [`instances`](#instances) | `min` and `max` instances. |

#### health

Any 2xx answer means up. The path starts with `/` and has no query or fragment. A path you set
is always the one checked. Left off:

| Provider | Checks |
| --- | --- |
| AWS | The load balancer checks `/`. |
| Google Cloud | Cloud Run's startup probe requests `/`. |
| VPS | The first deploy probes for a path and later deploys reuse it. See [Health checks](/docs/providers/vps#health-checks). |

#### instances

Whole numbers: `min` from 0, `max` from 1, `min` no more than `max`. Left off, `min` is 1 and
`max` is `min` (or 1), so the app runs one instance and never scales. A serverless app takes
no `instances`.

The numbers apply to every tier, so each preview keeps, and bills, the same `min` as
production.

| Provider | Between `min` and `max` |
| --- | --- |
| AWS | ECS starts at `min` and adds tasks above 1,000 requests a minute per task. `min` must be at least 1. |
| Google Cloud | Cloud Run's `min-instances` and `max-instances`, scaled on concurrent requests. `min: 0` scales to zero. |
| VPS | One container per app: both must be 1 or left off. |

## discovery.paths

The folders discovery runs to collect your resource declarations. Default: `infra` next to
the config. Setting `discovery.paths` replaces it.

```ts tab="TypeScript" tab-group="config" title="ocel.config.ts"
import { defineConfig } from "ocel/config";

export default defineConfig({
  slug: "my-app",
  discovery: { paths: ["packages/*/infra"] },
});
```

```json tab="JSON" title="ocel.json"
{
  "$schema": "https://ocel.dev/schema/ocel.schema.json",
  "slug": "my-app",
  "discovery": { "paths": ["packages/*/infra"] }
}
```

- A path is relative to the config and may be a glob. Every source file under it runs.
- A folder's language comes from its files: `.go` go, `.py` python, `.rs` rust, and `.ts`,
  `.tsx`, `.js`, `.jsx`, `.mjs` or `.cjs` js. A folder with two languages is an error.

## bindings

Binds a declared resource to one you already have instead of provisioning it. Keyed by type
(`postgres`, `bucket`, `kv`), then the declared name.

| Value | Binds to |
| --- | --- |
| `"@<name>"` | A record your own infrastructure published, with `ocel bindings set` or the SST and Pulumi packages. |
| `{ url }` | A postgres connection string, kept whole so `sslmode`, `options` and pooler parameters survive. |
| `{ host, database, username, password, port, tls }` | A postgres by its parts. `port` defaults to 5432. `tls.mode` is `require` or `verify-full`, and `tls.ca` a PEM CA. |
| `{ production: …, preview: … }` | Either of the two above, for that tier alone. The other tier provisions its own. |

A bucket binds to one in a store you already run: see
[Bucket](/docs/sdk/bucket#a-bucket-in-a-store-you-already-run). `ocel dev` always runs its own
resources.

```ts tab="TypeScript" tab-group="config" title="ocel.config.ts"
import { defineConfig } from "ocel/config";

export default defineConfig({
  slug: "my-app",
  bindings: {
    postgres: {
      analytics: "@warehouse",
      events: { url: { $env: "EVENTS_DATABASE_URL" } },
      orders: {
        production: {
          host: "db.abcdefghijkl.supabase.co",
          database: "postgres",
          username: "postgres",
          password: { $env: "SUPABASE_DB_PASSWORD" },
          tls: { mode: "verify-full", ca: { $env: "SUPABASE_CA" } },
        },
      },
    },
  },
});
```

```json tab="JSON" title="ocel.json"
{
  "$schema": "https://ocel.dev/schema/ocel.schema.json",
  "slug": "my-app",
  "bindings": {
    "postgres": {
      "analytics": "@warehouse",
      "events": { "url": { "$env": "EVENTS_DATABASE_URL" } },
      "orders": {
        "production": {
          "host": "db.abcdefghijkl.supabase.co",
          "database": "postgres",
          "username": "postgres",
          "password": { "$env": "SUPABASE_DB_PASSWORD" },
          "tls": { "mode": "verify-full", "ca": { "$env": "SUPABASE_CA" } }
        }
      }
    }
  }
}
```

- `{ "$env": "NAME" }` is a [variable](/docs/environments), set with `ocel env set`, and the
  only way a secret reaches a binding. Unset, the deploy stops and names the command. The app
  never receives it, and a name your code also declares is refused.
- Before building, the deploy checks an inline postgres's major version and a bucket's
  access, CORS and policy against what the code declares.

### A database branch per preview

Bind to a published record (`"orders": "@orders"`). Publish production's once with
`ocel bindings set < orders.json`, and each preview's with `--environment`, even before it
first deploys. A preview without one falls back to a preview-tier record, or is refused.

```yaml title=".github/workflows/preview.yml"
- run: |
    NAME=pr-${{ github.event.number }}
    neonctl branches get "$NAME" > /dev/null 2>&1 || neonctl branches create --name "$NAME"
    URL=$(neonctl connection-string "$NAME")
    jq -n --arg url "$URL" '{name: "orders", source: "neon", postgres: {url: $url}}' |
      ocel bindings set --preview --environment "$NAME"
- run: ocel preview up pr-${{ github.event.number }}
```

## protection

Which tiers ask for a password before they answer. Each tier is its own switch:

```ts tab="TypeScript" tab-group="config" title="ocel.config.ts"
import { defineConfig } from "ocel/config";

export default defineConfig({
  slug: "my-app",
  protection: { production: true, preview: true },
});
```

```json tab="JSON" title="ocel.json"
{
  "$schema": "https://ocel.dev/schema/ocel.schema.json",
  "slug": "my-app",
  "protection": { "production": true, "preview": true }
}
```

`protection.production` protects production and `protection.preview` protects every preview of the
project. A switch is nothing else: every deploy of its tier enforces it. With it on, the first
deploy of the tier creates the password and a key that signs sessions, and a later deploy keeps
them. With it off or left out, a deploy of the tier opens it again and warns that it does, and keeps
the password and bypass secrets so that turning it back on restores them. Turning it on never prints
the password; [`ocel protection`](/docs/cli/protection) shows it, rotates it, sets one you choose
and manages the secrets a test can send instead.

The tiers are separate: production and previews each hold a password and bypass secrets of their
own, and a preview password never opens production. An edge that cannot run the gate refuses the
deploy rather than serve a protected tier to anyone. On GCP with no edge in front, each Cloud Run
service checks every request itself against its tier's gate, which it reads from a secret it mounts
even while protection is off, so turning protection on reaches the services already running. Only
Node, Next and SvelteKit functions and containers can check it, so a protected tier with a Go,
Python or Rust function there is refused. While an unprotected one is still deployed, a protected
deploy warns, naming those functions, and changing the credentials or running
`ocel protection sync` writes the gate and then exits with an error naming them, until they are
destroyed.

A protected tier still lets through the request Next's `res.revalidate()` sends to its own URL: a
`HEAD` whose `x-prerender-revalidate` header holds the preview mode ID of the build the hostname
serves. Each Next build makes a new one, and the gate checks it against a SHA-256 of it the release
records. A `GET` with that header, or a `HEAD` with another build's ID, gets the login form like
any other request.

## lifecycle

`lifecycle.preBuild` runs once per deploy on your machine, after provisioning and before any
build: the place for a migration. Write the command alone, or as an object:

```ts tab="TypeScript" tab-group="config" title="ocel.config.ts"
import { defineConfig } from "ocel/config";

export default defineConfig({
  slug: "my-app",
  apps: [{ name: "web", path: "web" }],
  lifecycle: {
    preBuild: {
      command: "pnpm migrate",
      app: "web",
      previews: "persistent",
      timeout: "15m",
    },
  },
});
```

```json tab="JSON" title="ocel.json"
{
  "$schema": "https://ocel.dev/schema/ocel.schema.json",
  "slug": "my-app",
  "apps": [{ "name": "web", "path": "web" }],
  "lifecycle": {
    "preBuild": {
      "command": "pnpm migrate",
      "app": "web",
      "previews": "persistent",
      "timeout": "15m"
    }
  }
}
```

| Field | Required | Means |
| --- | --- | --- |
| `command` | Yes | The shell command. |
| `app` | | The app whose variables the command also receives, and whose directory it runs from. Left off, the project directory and the bindings alone. |
| `previews` | | `persistent` (default), `all` or `none`. Production always runs it. |
| `timeout` | | A duration such as `90s` or `15m`. Default 30 minutes. Past it, the command and everything it started are stopped. |

The command sees the deployed resources as your code does, as under
[`ocel run`](/docs/cli/run): `postgres("main").connectionString` is the deployed database.

- No port forwarding on the provider: it runs without bindings, and the deploy says so.
- Google Cloud: it can read, write and list bucket objects, but not sign URLs.
- A refused forward (database down, nothing deployed yet), a non-zero exit or a timeout stops
  the deploy before any build. Nothing is promoted; the current release keeps serving.
- Skipped by `ocel rollback`, `ocel env set`, `--dry` (listed only) and `--prebuilt` (run it
  yourself with `ocel run --env`).
- An npm `prebuild` script still runs per app. When both are set, the deploy warns once.
- Ephemeral previews share the preview tier's databases, hence the `persistent` default. Use
  `all` only when each preview [binds its own branch](#a-database-branch-per-preview).

The serving release runs against the new schema until promotion. Expand (add nullable or
defaulted columns), deploy, then contract (drop) in a later deploy. A rename takes three.

By hand: `ocel run --env production -- pnpm drizzle-kit migrate`.

## Another config per target

`ocel.<target>.config.ts` or `ocel.<target>.json` is the same project deployed somewhere else,
such as a box of your own beside your cloud. Point any command at it with `--config` or
`OCEL_CONFIG`:

```bash
ocel deploy --config ocel.vps.config.ts
```
