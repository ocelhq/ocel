---
title: Env sources
description: Read a tier's values from Infisical or a command, not only from ocel's own store.
---

An env source is where a tier's values come from. Each tier names its own under `envSource`,
and every one is optional:

| Tier | Left off | May also be |
| --- | --- | --- |
| `production` | `builtin` | `infisical`, `exec` |
| `preview` | `builtin` | `infisical`, `exec` |
| `dev` | `dotenv` | `infisical`, `exec` |

`builtin` is ocel's own store in your account, the one `ocel env set` writes. `dotenv` is the
project's `.env`, read only by `ocel dev` and `ocel run`.

```ts tab="TypeScript" tab-group="config" title="ocel.config.ts"
import { defineConfig } from "ocel/config";
import { infisical } from "ocel/env-source";
import awsProvider from "ocel/providers/aws";

export default defineConfig({
  slug: "my-app",
  provider: awsProvider(),
  envSource: {
    production: infisical({
      project: "4f1c2e0a-...",
      environment: "prod",
      auth: { identity: { identityId: "b7d0..." } },
    }),
    preview: "builtin",
    dev: infisical({ project: "4f1c2e0a-...", environment: "dev" }),
  },
  apps: [{ name: "web", path: "." }],
});
```

```json tab="JSON" title="ocel.json"
{
  "$schema": "https://ocel.dev/schema/ocel.schema.json",
  "slug": "my-app",
  "provider": "aws",
  "envSource": {
    "production": {
      "infisical": {
        "project": "4f1c2e0a-...",
        "environment": "prod",
        "auth": { "identity": { "identityId": "b7d0..." } }
      }
    },
    "preview": "builtin",
    "dev": { "infisical": { "project": "4f1c2e0a-...", "environment": "dev" } }
  },
  "apps": [{ "name": "web", "path": "." }]
}
```

## Who owns a value

Once a deployed tier reads from a source other than `builtin`, that source owns the tier's
values, and ocel keeps a copy it refreshes.

- `ocel env set`, `ocel env ui` and the console refuse to change a source's value, and link to
  where it lives, unless [`write`](#writing-into-infisical) allows it.
- `ocel env rm` and every remove in the UIs always refuse. ocel never deletes a key from a
  source.
- A value the tier held before switching, and the source lacks, is removed at the first sync.
  The deploy then names it as missing until you set it in the source.
- Credentials, and values that [reference](/docs/cli/env) another project's, stay ocel's own.
- A value set for one preview stays ocel's own and overrides the source for that preview:

```bash
ocel env set API_URL=https://pr-12.example.com --preview --environment pr-12
```

Switching back to `builtin` keeps every copied value as ocel's own.

From lowest to highest, a variable resolves to its default in code, then the tier's env
source, then a named environment's value, then `.env.local` in dev. The SOURCE column of
`ocel env ls` (Source in `ocel env ui`) says where each came from.

## Which env source a tier reads

A deploy reads the source the config names and registers it for the tier. The scheduled sync,
`ocel env sync` and the console's [connector](/docs/cli/connector) read the registered one,
never the config. So an `envSource` change takes effect at the next deploy; until then
`ocel env source` says the config names another.

## Infisical

| Option | Required | Means |
| --- | --- | --- |
| `project` | Yes | The Infisical project id. |
| `environment` | Yes | The Infisical environment slug, such as `prod`. |
| `path` | | The folder the project's values sit under. A variables folder such as `/web` reads beneath it. Default `/`. |
| `host` | | A self-hosted Infisical's base URL. Default `https://app.infisical.com`. |
| `auth` | Production and preview | The machine identity to sign in as: [`universal`](#universal-auth) or [`identity`](#identity-auth). Refused for `dev`. |
| `write` | | `"never"` (default), `"missing"` or `"values"`. See [below](#writing-into-infisical). Refused for `dev`. |

`dev` signs in as you and only reads. See [Dev](#dev).

- A missing or invalid declared value stops the deploy, linking each key to its Infisical
  folder, or opens the variables page where a browser can. With `write`, that page creates the
  key from what you type. A deploy in CI writes nothing to Infisical: it stops, naming each key
  to create there.
- A key nothing declares is drift: the deploy warns, and `ocel env ui` lists it as Undeclared.

### Writing into Infisical

| `write` | ocel may |
| --- | --- |
| `"never"` | Nothing. Change values in Infisical. |
| `"missing"` | Create a key a declaration names and Infisical lacks. Never overwrite one. |
| `"values"` | Create missing keys and update existing values. |

Then `ocel env set`, the variables page and the console write tier-wide values into
Infisical and sync at once:

```bash
ocel env set STRIPE_KEY=sk_live_...
```

- A value for one preview (`--environment`), and a credential, stay in ocel's own store.
- An update is refused if the secret changed in Infisical since ocel last copied it. Run
  `ocel env sync`, then set it again. An edit in the instant between check and write is
  overwritten; Infisical keeps it in version history.
- A key ocel never copied is filled in only while empty.
- An imported value is changed in the folder it lives in. ocel writes only a folder's own keys.
- No `write` deletes a key. Remove it in Infisical.
- Where the environment requires approval, the change waits for it. ocel says so, never sends
  it twice, and copies the value once approved.

### Credentials

A source's credentials live in ocel's own store, reach only the sync (never an app), and are
listed under "env source" in `ocel env ui`. Set them per tier:

```bash
ocel env set INFISICAL_CLIENT_ID=... INFISICAL_CLIENT_SECRET=...
ocel env set INFISICAL_CLIENT_ID=... INFISICAL_CLIENT_SECRET=... --preview
```

Or reference a shared project's, so one rotation covers every project:

```bash
ocel env ref INFISICAL_CLIENT_SECRET --target-project shared
```

The deploy stops, naming the credential, when it is unset or resolves to a value an env
source owns.

### Universal auth

A client id and secret, each the ocel variable that holds it. The only method a VPS can use,
since it has no cloud identity to prove.

```ts tab="TypeScript" tab-group="config" title="ocel.config.ts"
import { defineConfig } from "ocel/config";
import { infisical } from "ocel/env-source";
import vpsProvider from "ocel/providers/vps";

export default defineConfig({
  slug: "my-app",
  provider: vpsProvider({ ssh: { host: "203.0.113.10", user: "deploy" } }),
  envSource: {
    production: infisical({
      project: "4f1c2e0a-...",
      environment: "prod",
      auth: {
        universal: {
          clientId: { $env: "INFISICAL_CLIENT_ID" },
          clientSecret: { $env: "INFISICAL_CLIENT_SECRET" },
        },
      },
    }),
  },
  apps: [{ name: "web", path: "." }],
});
```

```json tab="JSON" title="ocel.json"
{
  "$schema": "https://ocel.dev/schema/ocel.schema.json",
  "slug": "my-app",
  "provider": { "vps": { "ssh": { "host": "203.0.113.10", "user": "deploy" } } },
  "envSource": {
    "production": {
      "infisical": {
        "project": "4f1c2e0a-...",
        "environment": "prod",
        "auth": {
          "universal": {
            "clientId": { "$env": "INFISICAL_CLIENT_ID" },
            "clientSecret": { "$env": "INFISICAL_CLIENT_SECRET" }
          }
        }
      }
    }
  },
  "apps": [{ "name": "web", "path": "." }]
}
```

Create a Universal Auth identity in Infisical, give it access to the project, and set its
client id and secret as [credentials](#credentials).

### Identity auth

The target's own cloud identity signs in as the Infisical machine identity `identityId`
names, so no secret is stored. The example at the top of this page uses it, and the same
config works on AWS and Google Cloud. What Infisical must allow depends on the cloud.

#### On AWS

Create an **AWS Auth** identity in Infisical with access to the project. Under **Allowed
Principal ARNs**, list:

- The role or user you deploy as (`aws sts get-caller-identity`). It signs in for deploys and
  `ocel env sync`.
- The sync's role, which reads the source once a minute: list
  `arn:aws:iam::<account>:role/<namespace>-env-sync` (`-preview` suffix for preview). The
  namespace is `ocel` unless you set `OCEL_NAMESPACE`. The first deploy that registers a
  scheduled source makes the role, and its name is fixed, so you can list it before then.
- If the console writes into Infisical through a [connector](/docs/cli/connector), the
  `ConnectorRole` of the `<namespace>-connector` stack.

Or allow every principal in the account with `arn:aws:iam::<account>:*`.

#### On Google Cloud

Create a **GCP ID Token Auth** identity in Infisical with access to the project. Under
**Allowed Service Account Emails**, list:

- The service account you deploy as. It signs in for deploys and `ocel env sync`.
- The sync's service account, which reads the source once a minute. Its email is a hash, so
  find it by its display name, `ocel env source sync (<namespace>, <tier>)` (command below).
- If the console writes into Infisical through a [connector](/docs/cli/connector),
  `<namespace>-connector@<project>.iam.gserviceaccount.com`.

```bash
gcloud iam service-accounts list --project my-project \
  --filter='displayName="ocel env source sync (ocel, production)"' --format='value(email)'
```

Leave **Allowed Projects** and **Allowed Zones** empty: they match only Compute Engine
instances. A personal `gcloud auth application-default login` has no service account to
prove, so deploy as one, by key or impersonation:

```bash
gcloud auth application-default login --impersonate-service-account=deploy@my-project.iam.gserviceaccount.com
```

## How fresh a value is

| Where | Picks up a change |
| --- | --- |
| A deploy, or resuming one from the variables page | Reads the source first. |
| Your account, between deploys | The sync reads every minute and writes what changed: a scheduled function on AWS, a Cloud Run service on Google Cloud, a systemd unit on a VPS. On AWS and Google Cloud the first deploy that registers a scheduled source adds it, and `ocel bootstrap status` lists it as `env-source-sync`; `ocel bootstrap` installs it on a VPS. |
| A running app | A secret within another 60 seconds, so about two minutes from Infisical. Any other value at the next deploy. |

- Infisical down or throttling: the last values stay and the sync backs off.
- A deploy switching to a source it cannot read fails, and the sync keeps the old source.
  Except when the new source's credential is unset: the tier switches, so `ocel env set` can
  fill it.

```bash
ocel env source            # production's source, last sync, last error
ocel env source --preview
ocel env sync              # read it now
```

## exec

A command whose output is the tier's values, run on the machine that deploys, once per
variables folder, with `{folder}` replaced by that folder.

```ts tab="TypeScript" tab-group="config" title="ocel.config.ts"
import { defineConfig } from "ocel/config";
import { exec } from "ocel/env-source";
import awsProvider from "ocel/providers/aws";

export default defineConfig({
  slug: "my-app",
  provider: awsProvider(),
  envSource: {
    production: exec({ command: ["./scripts/env.sh", "{folder}"], format: "dotenv" }),
  },
  apps: [{ name: "web", path: "." }],
});
```

```json tab="JSON" title="ocel.json"
{
  "$schema": "https://ocel.dev/schema/ocel.schema.json",
  "slug": "my-app",
  "provider": "aws",
  "envSource": {
    "production": {
      "exec": { "command": ["./scripts/env.sh", "{folder}"], "format": "dotenv" }
    }
  },
  "apps": [{ "name": "web", "path": "." }]
}
```

| Option | Required | Means |
| --- | --- | --- |
| `command` | Yes | The command and its arguments, as a list. |
| `format` | Yes | `json` (an object of names to values) or `dotenv` (`KEY=VALUE` lines). |

- Nothing in your account can run it, so a deployed tier reads it only at a deploy. There is
  no scheduled sync, and `ocel env sync` refuses.
- A failing command is named with its exit status, never its output, which may hold a value.
  Run it yourself to see why.

## Dev

`ocel dev` and `ocel run` read the dev tier's source once, at start, on your machine.
Infisical signs in as you, with `INFISICAL_TOKEN` or else the `infisical` CLI's login:

```bash
infisical login
ocel dev
```

`exec` runs on your machine. Under `infisical` or `exec`, `.env` is not read. `.env.local` is
read under every source, and wins.
