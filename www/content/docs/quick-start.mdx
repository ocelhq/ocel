By the end of this page a Next.js app is running in your AWS account, with a URL.

## Before you start

| You need | Why |
| --- | --- |
| Node 20 or newer | Ocel builds your Next.js app with it |
| An AWS account | Where the app runs |
| AWS credentials in your shell | Ocel provisions with them |

Check the credentials are visible:

```bash
aws sts get-caller-identity
```

## Install

```bash
curl -fsSL https://ocel.dev/install.sh | sh
ocel --version
```

[Homebrew and npm](/docs/install) install the same binary.

## Deploy

```bash
npx create-next-app@latest my-app
cd my-app
ocel deploy
```

The first deploy sets up what the project is missing, asks before each step, and then deploys:

- **The project.** There is no `ocel.json` yet, so it asks where `my-app` should deploy, writes one, and adds the ocel SDK to your dependencies. The slug is the project's identity in your account. Every resource Ocel creates is keyed on it, so pick it once.
- **The shared infrastructure.** Your account has none yet, so it offers to run `ocel bootstrap production`. Expect a few minutes for that one. Later deploys reuse it.

Answer no to any of them and nothing changes; the deploy names the command to run when you're ready.

```json title="ocel.json"
{
  "$schema": "https://ocel.dev/schema/0.0.1/ocel.schema.json",
  "slug": "my-app",
  "provider": "aws"
}
```

```txt
→ web › Building
✓ web  24s
→ web › Provisioning
✓ web › Provisioning  21s
→ Promotion › Finalizing
✓ Promotion  2s

✓ Deployed in 54s

  https://my-app.example.com
```

Open the URL. That is your app, in your account.

In a script or in CI nothing is asked, so a missing step stops the deploy and names the command
that sets it up. Run them first there:

```bash
ocel init --provider aws
ocel bootstrap production
ocel deploy
```

`ocel lock` pins the providers this CLI runs; commit its result and every machine and every CI
run fetches the same bytes.

## Change something and deploy again

Edit a page, then:

```bash
ocel deploy
```

The build runs again, provisioning changes nothing unless the app now asks for something new, and traffic moves to the new deployment. The previous one is still there:

```bash
ocel promotions ls
ocel rollback
```

## Try a branch

```bash
git switch -c checkout
ocel preview
```

The preview is a full deployment beside production, named after the branch, on its own hostname. `ocel preview rm` tears it down and leaves production alone. Give it a name, as in `ocel preview pr-12`, to address it from any branch; [`ocel preview`](/docs/cli/preview) covers names and persistent previews.

## Clean up

```bash
ocel destroy production
```

This removes everything the project created in your account and nothing else.
