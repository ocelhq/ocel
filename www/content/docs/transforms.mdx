---
title: Transforms
description: Patch the cloud resources ocel provisions.
---

A transform is a module that patches the cloud resources ocel is about to provision, keyed by
the provider that creates them. List the modules at the root of the config; a later module
wins where two patch the same field.

```ts tab="TypeScript" tab-group="config" title="ocel.config.ts"
import { defineConfig } from "ocel/config";
import awsProvider from "ocel/providers/aws";

export default defineConfig({
  slug: "my-app",
  transforms: ["./transforms/defaults.transform.ts"],
  provider: awsProvider(),
  apps: [{ name: "web", path: "." }],
});
```

```json tab="JSON" title="ocel.json"
{
  "$schema": "https://ocel.dev/schema/ocel.schema.json",
  "slug": "my-app",
  "transforms": ["./transforms/defaults.transform.ts"],
  "provider": "aws",
  "apps": [{ "name": "web", "path": "." }]
}
```

```bash
pnpm add -D @ocel/transforms
```

## A module

```ts title="transforms/defaults.transform.ts"
import { defineTransform } from "@ocel/transforms";

export default defineTransform({
  aws: {
    function: { lambda: { memorySize: 2048, timeout: 60 } },
  },
});
```

`aws` is the provider, `function` the ocel resource, and `lambda` the Pulumi resource created
for it. Under it go `aws.lambda.Function`'s own args, typed from `@pulumi/aws`.

| ocel resource | Pulumi resources |
| --- | --- |
| `function` | `lambda`, `url`, `urlPermission`, `logGroup`, `role` |
| `container` | `task`, `service`, `targetGroup`, `rule`, `role` |
| `bucket` | `bucket`, `publicAccessBlock`, `cors`, `uploadCompleterRole`, `uploadCompleterS3Policy`, `uploadCompleterSessionsPolicy`, `uploadCompleterLogsPolicy`, `uploadCompleterLogGroup`, `uploadCompleter`, `uploadCompleterPermission`, `notification` |
| `postgres` | `securityGroup`, `subnetGroup`, `cluster`, `instance` |
| `kv` | `securityGroup`, `subnetGroup`, `parameterGroup`, `replicationGroup` |
| `network` | `vpc`, `internetGateway`, `publicSubnet`, `privateSubnet`, `isolatedSubnet`, `publicRouteTable`, `privateRouteTable`, `isolatedRouteTable`, `s3Endpoint`, `dynamodbEndpoint`, `natGateway`, `natAddress` |

The deploy is refused when:

- a patch names a field ocel fills from the build (the role it created, the code it uploaded,
  the environment it sealed). Those fields are not on the type.
- a module has no branch for the project's provider, or a patch reaches no resource the
  deploy provisions.
- two functions in an app patch `role`, which they share, differently.
- a kv patch runs [one node](/docs/providers/aws#kv-stores) without also turning
  `automaticFailoverEnabled` and `multiAzEnabled` off.

A kv store's token, port, TLS, engine version, parameters and node type (picked by `memory`)
stay ocel's. Its node count is yours: one node halves the cost and loses the data when
ElastiCache replaces the node.

A container app's `task`, `service`, `targetGroup` and `rule` are its Fargate task definition and
service and the target group and listener rule that route its requests. What ocel fills from the
build or the tier's network is not on the type: the container definitions, roles, network
configuration, cluster and desired count, and the target group's and rule's routing. Its `role`
is the task role, which a container app has once it reaches a binding, a task or a live variable.

## The network

On AWS, `network` patches the tier's [VPC](/docs/providers/aws#the-network) and the function
network's NAT gateways. A subnet or route table key reaches that kind in every zone, so
`privateSubnet` patches both private subnets. Its block, zones, routes, endpoints' route tables
and the NAT gateways' placement stay ocel's, and so do the VPC's DNS settings and tenancy, a
subnet's IPv4 addressing and a NAT gateway's public connectivity: the databases, caches and
functions of every project in the tier depend on them, and changing some would replace the VPC
or its subnets under them. What has to differ from one zone to the next stays ocel's too, since
one patch would set it alike in each: a subnet's IPv6 block and Outpost, a NAT gateway's private
and secondary addresses, and an elastic IP's own address. So does what would bind an elastic IP
to anything but its NAT gateway.

```ts title="transforms/network.transform.ts"
import { defineTransform } from "@ocel/transforms";

export default defineTransform({
  tags: { "acme:cost-center": "platform" },
  aws: {
    network: {
      vpc: { enableNetworkAddressUsageMetrics: true },
      s3Endpoint: { policy: JSON.stringify({ Statement: [/* … */] }) },
    },
  },
});
```

The network belongs to the tier, not to a project:

- A rule's `if` sees the tier and no `env` or `app` for it.
- Every project deployed to the tier should list the same network patches: a deploy whose patches
  differ from the ones the network carries provisions it again with its own. A deploy whose
  transforms patch nothing in it leaves it as it is.
- A changed patch takes effect at the next deploy of anything that runs in the network.
- A patch cannot be filled from `bindings`: no project's records reach a tier's network.

## On a VPS

A box has no Pulumi resources, so the `vps` branch patches the container and volume a
`postgres`, `bucket` or `kv` store runs as.

```ts title="transforms/stack.transform.ts"
import { defineTransform } from "@ocel/transforms";

export default defineTransform({
  vps: {
    postgres: {
      container: {
        image: "pgvector/pgvector@sha256:…",
        args: ["-c", "max_connections=200"],
        memory: "2g",
      },
    },
  },
});
```

| Part | You can set |
| --- | --- |
| `container` | `image`, `args`, `env`, `memory`, `cpus`, `shmSize` |
| `volume` | `driver`, `driverOpts` |

- `image` must be pinned by digest.
- A `volume` whose `driverOpts` bind a path on the box (`o: "bind"`, or a `device` path) is
  refused: the [deploy login](/docs/providers/vps#the-deploy-login) mounts only the
  directories bootstrap lists.
- The container's name, network, labels, published ports and mounts stay ocel's, and so do the
  variables a binding depends on:

  | Resource | Reserved variables |
  | --- | --- |
  | `postgres` | `POSTGRES_USER`, `POSTGRES_DB`, `POSTGRES_PASSWORD`, `POSTGRES_HOST_AUTH_METHOD`, `PGDATA` |
  | `bucket` | `RUSTFS_ACCESS_KEY`, `RUSTFS_SECRET_KEY`, `RUSTFS_ADDRESS`, `RUSTFS_REGION`, `RUSTFS_VOLUMES` |
  | `kv` | `VALKEY_EXTRA_FLAGS` |

- One store holds every bucket the project declares, so `bucket` shapes that one container
  and volume. Gate a rule on the environment, not on a bucket.
- A kv store's `args` come after ocel's settings, and one that sets any of them is refused: the
  user and password, `maxmemory` and its policy, persistence, the data directory, the listener.
- `memory` caps the whole container. For kv, give it well over twice the store's own `memory`:
  a background save forks the server, and the copy can grow to the size of the data.
- `tags` become labels on the container and volume. Every value is literal; a box has no
  binding outputs to fill one from.

## Gates and tags

A rule can take an `if` gate, decided from the environment being deployed and the resource's
app, and `tags` to union into every resource it reaches. Write a list where one rule is not
enough:

```ts title="transforms/defaults.transform.ts"
import { defineTransform } from "@ocel/transforms";

export default defineTransform([
  { tags: { "acme:cost-center": "platform" } },
  {
    if: ({ envTier }) => envTier === "production",
    aws: {
      postgres: {
        cluster: { serverlessv2ScalingConfiguration: { minCapacity: 2, maxCapacity: 16 } },
      },
    },
  },
]);
```

## Placing a function in your own VPC

On AWS, a serverless app that uses a `postgres` or `kv` ocel provisions joins the
[tier's network](/docs/providers/aws#the-network) through the
[function network](/docs/providers/aws#serverless-apps-and-the-vpc). A transform that
sets `vpcConfig` on a function overrides that: the function runs in the subnets and security
groups the transform names, as in the example below, and ocel adds nothing to it. A function the
transform does not name keeps the automatic attach. A `vpcConfig` needs at least one subnet and
one security group.

## Reading what your own infrastructure published

The callback form fills a field from a record your own infrastructure published:

```ts title="transforms/network.transform.ts"
import { defineTransform } from "@ocel/transforms";

export default defineTransform(({ bindings }) => ({
  aws: {
    function: {
      lambda: {
        vpcConfig: {
          subnetIds: bindings.custom.network.subnetIds,
          securityGroupIds: bindings.custom.network.securityGroupIds,
        },
      },
    },
  },
}));
```

| Reads | The record |
| --- | --- |
| `bindings.<type>.<name>` | Bound to a resource under `bindings` in your config. |
| `bindings.custom.<name>` | Published with `bind.custom` by [`@ocel/sst`](/docs/sdk) or [`@ocel/pulumi`](/docs/sdk), for nothing declared. |

The deploy resolves the record, not the module. A resource ocel provisions itself cannot be
read this way: ocel publishes it after the transforms run. `ocel bindings generate` writes the
names and types down, so the module is checked as you write it.
