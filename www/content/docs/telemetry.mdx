---
title: Telemetry
description: What the ocel CLI sends, what it never sends, and how to turn it off.
---

The CLI records one event each time a command finishes: which command ran, how long it took and whether it succeeded. `ocel init`, `ocel dev` and `ocel deploy` each record one more, saying what kind of project was set up, how a dev session went and what a deploy did. We use them to see which commands people use and which ones fail, so we know where to spend time.

Each event carries a random install ID, kept in your user config directory, a random ID of its own, and the time it was recorded. No account, email or machine name is attached, and no person profile is created.

## Events

| Event               | Meaning                                                                                                          |
| ------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `command_completed` | An `ocel` command finished, whether it passed or not.                                                            |
| `dev_session_ended` | An `ocel dev` session stopped, for whatever reason. A second `ocel dev` that joins a running one sends its own.  |
| `init_completed`    | `ocel init` wrote a project. It is not sent when init fails.                                                     |
| `deploy_completed`  | An `ocel deploy` or preview deploy ran, whether it succeeded or failed. Dry runs and declined runs send nothing. |

## Properties

Every property on every event is in this table. The CLI refuses to send one that is not.

| Property                  | Meaning                                                                                                                                                                                 |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `command`                 | The command path, such as `deploy` or `env set`. `help` when no command ran: plain `ocel`, `ocel --help`, or an unknown top-level command.                                              |
| `flags`                   | The names of the flags you set, sorted. Never their values.                                                                                                                             |
| `exit_code`               | The process exit code.                                                                                                                                                                  |
| `error_code`              | The stable error code of the failure, such as `internal`. Empty when the command succeeded.                                                                                             |
| `duration_ms`             | How long the command ran, or the dev session lasted, in milliseconds.                                                                                                                   |
| `json`                    | Whether JSON output was requested.                                                                                                                                                      |
| `tty`                     | Whether standard output was a terminal.                                                                                                                                                 |
| `skill_installed`         | Whether the project holds the ocel skill in `.claude/skills/ocel` or `.agents/skills/ocel`. Only the yes or no is sent, never the path.                                                 |
| `reloads`                 | How many times the dev session restarted your app because its environment changed.                                                                                                      |
| `resource_kinds`          | The kinds of resource the app declared when the dev session ended, such as `postgres` or `bucket`, sorted. Never their names. Empty for an `ocel dev` that joined a running one.        |
| `error_codes`             | How many times each [error code](/docs/errors) was reported during the dev session, such as `{"variables.missing": 2}`. Stopping the session and failures with no code are not counted. |
| `language`                | The language of the project `ocel init` set up: `node`, `go`, `python` or `rust`. Empty when none was named or detected.                                                                |
| `package_manager`         | The tool that adds the SDK for that language: `npm`, `pnpm`, `yarn` or `bun` for node, otherwise `go`, `uv` or `cargo`. Empty with no language.                                         |
| `provider`                | The provider the project deploys through: `aws`, `gcp` or `vps`. Set by `ocel init` and `ocel deploy`.                                                                                  |
| `config_format`           | The format of the config file `ocel init` wrote: `json`, `ts` or `yaml`.                                                                                                                |
| `success`                 | Whether the deploy succeeded.                                                                                                                                                           |
| `target`                  | `production` for `ocel deploy`, `preview` for a preview deploy.                                                                                                                         |
| `frameworks`              | The frameworks of the apps deployed, such as `next`, sorted and without repeats. Empty when no app uses one.                                                                            |
| `languages`               | The languages of the apps deployed: `js`, `go`, `python` or `rust`, sorted and without repeats.                                                                                         |
| `app_count`               | How many apps the project deploys.                                                                                                                                                      |
| `resource_counts`         | How many resources of each kind the deploy manages, such as `{"bucket": 1}`. Never their names.                                                                                         |
| `plan_actions`            | How many resources the plan creates, updates and deletes, as `{"create": 2, "update": 1, "delete": 0}`.                                                                                 |
| `phase_ms`                | How long each phase of the deploy took in milliseconds, such as `{"build": 4200, "provision": 61000}`.                                                                                  |
| `first_deploy`            | Whether this install had not deployed successfully before.                                                                                                                              |
| `assumed`                 | The ids of the defaults the deploy assumed because you did not set them, sorted and without repeats.                                                                                    |
| `cli_version`             | The version of the CLI.                                                                                                                                                                 |
| `os`                      | The operating system, such as `linux`.                                                                                                                                                  |
| `arch`                    | The CPU architecture, such as `arm64`.                                                                                                                                                  |
| `agent`                   | The coding agent that ran the command, such as `claude-code`. Empty when none was detected.                                                                                             |
| `ci`                      | The CI system the command ran in, such as `github-actions`. Empty outside CI.                                                                                                           |
| `$process_person_profile` | Always `false`. It tells the analytics service not to build a profile for the install ID.                                                                                               |

## What is never sent

- Error text, or the detail of a run summary.
- File paths.
- Project, app, resource or variable names.
- Flag values. Only the flag names are sent.
- Emails or tokens.

## Turn it off

Set `OCEL_TELEMETRY=0` or `OCEL_TELEMETRY=false`:

```bash
export OCEL_TELEMETRY=0
```

With telemetry off, the CLI records and sends nothing.

## See what would be sent

Set `OCEL_TELEMETRY=debug` and the CLI prints each event to stderr instead of sending it:

```bash
OCEL_TELEMETRY=debug ocel deploy
```
