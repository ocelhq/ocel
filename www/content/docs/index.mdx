## Zero infrastructure code

You write one config. It names a target, a cloud or a server, and nothing about how to build there. Your app does not know or care which, nor should it have to. Swapping targets changes the provider and nothing else:

<Compare>
<div>

```ts tab="TypeScript" tab-group="config" title="ocel.config.ts" lineNumbers
import { defineConfig } from "ocel/config";
import awsProvider from "ocel/providers/aws"; // [!code --]

export default defineConfig({
  slug: "acme",
  provider: awsProvider(), // [!code --]
  apps: [{ name: "web", path: "." }],
});
```

```json tab="JSON" title="ocel.json" lineNumbers

  "$schema": "https://ocel.dev/schema/ocel.schema.json",
  "slug": "acme",
  "provider": "aws", // [!code --]
```

## Application defined infrastructure

A database or a bucket is a function call in your app. Declare it once in a [discovery folder](/docs/configuration#discoverypaths), import it where you use it, and the call is what provisions it. There is no other definition of it anywhere.

```ts title="resources/index.ts"
import { postgres } from "ocel/postgres";

export const db = postgres("main");
```

```ts title="src/server.ts"
import express from "express";
import { db } from "../resources";

const app = express();

app.get("/documents", async (_req, res) => {
  const { rows } = await db.query("select * from documents");
  res.json(rows);
});

app.listen(3000);
```

This works whether you deploy to a cloud like AWS or VPS. [Learn more about the SDK](/docs/sdk).

## The stack comes up with dev

One command: `ocel dev` starts the postgres and buckets your code declares alongside your app, on your machine. Docker is the only prerequisite, and only when the app declares a resource.
