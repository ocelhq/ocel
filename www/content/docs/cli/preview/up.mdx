---
title: "ocel preview up"
description: "Deploy or refresh a preview."
---

```bash
ocel preview up [name] [flags]
```

Without a name the preview is the current branch's. A name, a DNS label with no `--`, addresses one preview from any branch.

A preview has resources of its own and is ephemeral: torn down without a question. `--persistent` deploys one that asks first, such as staging. A preview keeps the lifecycle it was created with.

`--dry` builds, prints every change and stops.

## Arguments

| Argument | Takes |
| --- | --- |
| `[name]` | Optional |

## Flags

| Flag | Type | Default | Description |
| --- | --- | --- | --- |
| `--dry` | `bool` | `false` | Build, print every change this would make, and stop |
| `--no-wait` | `bool` | `false` | On Ocel Cloud, start the job, print its link and return without waiting for it to end |
| `--persistent` | `bool` | `false` | Deploy a persistent preview: a confirmation before it is torn down |
| `--prebuilt` | `bool` | `false` | Deploy the existing .ocel/output instead of building first (produce it with ocel build) |
| `-y, --yes` | `bool` | `false` | Consent in advance to any confirmation this command would ask for |

Every command also takes the [global flags](/docs/cli#global-flags).

## Behaviour

- Changes state.
- Asks before it changes anything: `--yes` consents in advance, and `--dry` prints what it would change and stops.
- Under `--json` it prints its run events as NDJSON, one per line, and `ocel schema preview up` prints the JSON Schema of one line.
