---
title: ocel env
description: Manage this project's variable values.
---

```bash
ocel env ls
ocel env set LOG_LEVEL=debug
ocel env ui --preview
```

Values live in your own account, one store per deployed tier. Every command reads
production unless you pass `--preview`; `--environment <name>` narrows a preview command to
one named environment.

| Command | What it does |
| --- | --- |
| `ls` | List values without revealing them, with the source each one comes from. |
| `get <KEY>` | Inspect a value; `--reveal` prints it. |
| `set <KEY=VALUE>...` | Set values. |
| `rm <KEY>` | Remove a value. |
| `ref <KEY>` | Read a value another project holds. |
| `refs <KEY>` | List the references to a value. |
| `history <KEY>` | List a value's versions. |
| `ui` | Open the variable editor in your browser. |
| `source` | Show where a tier's values are read from, and how its last sync went. |
| `sync` | Read a tier's env source into its values now. |

When a tier reads from an [env source](/docs/env-sources) other than ocel's own store,
`set` and `rm` refuse a value that source owns and name where to change it. `ocel dev`
reads the dev tier's source on your machine instead.
