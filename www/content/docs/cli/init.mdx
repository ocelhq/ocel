---
title: ocel init
description: Make this directory deployable.
---

```bash
ocel init --provider aws
```

Writes the [config](/docs/configuration) here, naming the provider you gave and a slug — this
directory's name unless you pass one — and adds the ocel SDK with your language's own package
manager. A project built with node gets `ocel.config.ts`, and any other gets `ocel.json`. It
runs entirely offline: it neither signs you in nor contacts the console.

```bash
ocel init my-app --provider vps
```

| Flag | What it does |
| --- | --- |
| `--provider` | The provider this project deploys through: `aws`, `gcp` or `vps`. Required. |
| `--option` | An option the provider cannot deploy without, as `name=value`: `region` for `gcp`, `ssh` for `vps`. Repeat it for each. On a terminal, init asks for any you leave out; under `--json` or with no terminal, it fails with [`input_required`](/docs/errors/input_required). |
| `--lang` | The language of this project (`go`, `rust`, `python`, `node`), when no manifest here says. |
| `--format` | Write the config as `ts`, `json` or [`yaml`](/docs/configuration#yaml) instead of the default — the same document in each. `ts` needs node. |

```bash
ocel init --provider gcp --option region=europe-west1
```

Then pin the providers this CLI runs, and commit the result:

```bash
ocel lock
```
