---
title: "ocel deploy"
description: "Deploy this project to your own infrastructure."
---

```bash
ocel deploy [flags]
```

Provisions the resources the project declares, builds the apps, and releases the result into your provider account. Every deploy is kept: list them with `ocel promotions ls`, return to one with `ocel rollback`.

`--dry` builds, then prints every change the deploy would make to your account and stops.

## Flags

| Flag | Type | Default | Description |
| --- | --- | --- | --- |
| `--dry` | `bool` | `false` | Build, then print every change this would make to your account and stop without applying any of it |
| `--no-wait` | `bool` | `false` | On a runner, start the job, print its link and return without waiting for it to end |
| `--prebuilt` | `bool` | `false` | Deploy the existing .ocel/output instead of building first (produce it with ocel build) |
| `--remote` | `bool` | `false` | Run this as a job on the runner the console binds to the project's tier: upload the source, start the job and follow it |
| `--tag` | `string` |  | Mark this deploy with an immutable label to roll back to by name (ocel rollback `--tag`) |
| `-y, --yes` | `bool` | `false` | Consent in advance to any confirmation this command would ask for |

Every command also takes the [global flags](/docs/cli#global-flags).

## Behaviour

- Changes state.
- Asks before it changes anything: `--yes` consents in advance, and `--dry` prints what it would change and stops.
- Under `--json` it prints its run events as NDJSON, one per line, and `ocel schema deploy` prints the JSON Schema of one line.
