---
title: project.invalid_config
description: The project's config is not valid.
---

Ocel read the config and refused it. The message says why, and the error's `hint` names the field when one is at fault: a missing or malformed `slug`, an app name that is not a DNS label, two config files in one directory, a file that is not valid JSON, a `provider`, `domains`, `bindings` or `registry` entry that does not fit, a `provider` or another project's `slug` in a project an Ocel Cloud job runs, a serverless app whose framework ocel cannot [detect](/docs/configuration#how-ocel-finds-each-app) and that sets no `framework`, or an `ocel build` of a project that names no `apps` and whose root holds no app ocel detects.

## Fix

Correct the field the message names and run the command again. In `ocel.config.ts` the types make an editor flag these before a run, and in `ocel.json` the `$schema` line does. See [configuration](/docs/configuration).
