---
title: Errors
description: Every error code the CLI reports, what it means and how to recover.
---

A failed run carries a `code`, and with it a `docsUrl` that points at the page below; an interrupted run has none. The code stays the same between releases, so a script or an agent can branch on it. The message and the `hint` change.

A failure with no code reports `internal`. It has no page, because it means Ocel itself broke.

## Confirmation and input

| Code | Meaning |
| --- | --- |
| [`confirmation_required`](/docs/errors/confirmation_required) | A command needs a confirmation it cannot ask for. |
| [`confirmation_bypass_mismatch`](/docs/errors/confirmation_bypass_mismatch) | `OCEL_DESTROY_BYPASS_CONFIRMATION` is set, but not to the thing being destroyed. |
| [`input_required`](/docs/errors/input_required) | A command needs a value it cannot ask for. |
| [`usage`](/docs/errors/usage) | The command line did not parse. |

## A job's own codes

A job that fails ends the command with [`job.failed`](/docs/errors/job.failed), and its message names the job's own code: one of the CLI's codes above, from the run inside the job, or one of these, from the runner or from Ocel Cloud.

| Code | Meaning |
| --- | --- |
| [`job.source`](/docs/errors/job.source) | The runner could not unpack the job's source. |
| [`job.run`](/docs/errors/job.run) | The ocel run inside the job failed without naming an error code. |
| [`job.agent`](/docs/errors/job.agent) | The runner's job agent failed the job. |
| [`job.timeout`](/docs/errors/job.timeout) | The job ran longer than its token allows, and was stopped. |
| [`job.interrupted`](/docs/errors/job.interrupted) | The runner lost the job before it ended. |
| [`cloud.preview_limit`](/docs/errors/cloud.preview_limit) | The project runs as many preview environments as the organization's plan allows. |
