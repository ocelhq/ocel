```bash
ocel connector add
```

Puts a connector on the target this project's config names, and tells the console where to
dial it. Sign in and link the directory first, with [`ocel login`](/docs/cli/login) and
[`ocel link`](/docs/link).

What the console may do through the connector is decided when you add it. Read variables it
always may; write them it may unless you withhold that, and read a secret value back in the
clear only if you grant it:

```bash
ocel connector add --allow-write=false --allow-reveal
```

`--compute` picks what the connector runs on, `serverless` or `container`, and the provider's own
default when you name neither.

## One connector per target

A target has one connector. A second `add` against the same target repoints the one
already there rather than adding another — so it is also how you change what the
console may do, and how you finish an add that stopped partway.
