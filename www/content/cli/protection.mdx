```bash
ocel protection
ocel protection password
ocel protection password rotate
printf '%s' "$PASSWORD" | ocel protection password set
ocel protection bypass create
ocel protection bypass ls
ocel protection bypass revoke <id>
ocel protection sync
ocel protection password --preview
```

Production and previews can each ask for a password before they answer. Whether one does is a switch
in the project's config, [`protection.production`](/docs/configuration#protection) or
`protection.preview`, and every deploy of that tier enforces it. With it on, the first deploy
creates a password and never prints it; with it off or left out, the next deploy opens the tier
again and says so. It keeps the password and the bypass secrets, so turning protection back on
restores them. The commands above never turn protection on or off. They show the password, replace
it, and manage the bypass secrets a machine can send in its place.

Each tier has credentials of its own: a preview password and a preview bypass secret never open
production, and the other way round. A command addresses production unless you pass `--preview`,
as [`ocel env`](/docs/cli/env) does. Each refuses while the config does not protect the tier it
addresses, and while the last deploy of that tier left it open, until a deploy with protection on
restores the credentials.

A visitor to a protected tier gets a login page; entering the password opens a session for seven
days. A request that carries the password as HTTP Basic credentials, with any user name, or a bypass
secret in the `x-ocel-bypass` header, passes without a session, and a bypass request that also
sends `x-ocel-set-bypass-cookie: true` is answered with a redirect that opens one. A request that
fails never reaches your app, and neither does the password. Without JavaScript the login page
offers the browser's own password prompt. The gate answers before the edge looks in its cache, so a
cached page never reaches a visitor without credentials, and everything it answers is marked
`Cache-Control: private, no-store` and `X-Robots-Tag: noindex`.

`ocel protection` says for both tiers whether protection is on and why, whether a password is set,
which bypass secrets exist by id, and for the edge that serves each tier whether it holds the
current credentials. `password` prints the password alone, so it pipes. `password rotate` replaces
it with a generated one and prints it; `password set` takes one you choose from standard input, of
at least 12 characters and at most 256 bytes. Both end every login session. `bypass create` prints a
secret once; a tier holds at most eight, and `bypass revoke` ends one along with every session.
Creating a bypass secret leaves sessions alone.

A change is recorded and then published to the edge, so it takes effect without a deploy. The
Cloudflare worker may serve the old credentials for up to five seconds, and a GCP load balancer
takes a few minutes to roll its gate plugin out. A Cloud Run service with no edge in front
reads its gate from a mounted secret at most five seconds after it last read it, and
[Configure secrets for services](https://docs.cloud.google.com/run/docs/configuring/services/secrets)
says Cloud Run fetches a mounted secret from Secret Manager each time it is read. If an edge cannot
be reached the command still prints any secret it generated, exits with an error, and leaves the
edge shown as pending until `ocel protection sync` publishes the recorded credentials again.

An edge has to run the gate for a tier to be protected on it, and a deploy through one that does
not is refused. On GCP a tier served on its own Cloud Run URL is gated by its own service: the gate
lives in a Secret Manager secret of that tier that every container and Node, Next or SvelteKit
function of the tier mounts, even while protection is off, so turning it on or changing the
credentials reaches the running instances without a deploy. A Go, Python or Rust function checks no
gate: a protected tier with one is refused, and while an unprotected one is still deployed,
`ocel protection` names it rather than calling the tier protected. A change or `ocel protection sync`
then still writes the gate to every service that checks it, and exits with an error naming those
functions, until they are destroyed.
