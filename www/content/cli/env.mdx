```bash
ocel env ls
ocel env set LOG_LEVEL=debug
ocel env ui --preview
```

Values live in your own account, one store per deployed tier. Commands address production unless
you pass:

| Flag | Addresses |
| --- | --- |
| `--preview` | previews |
| `--preview --environment pr-12` | one preview, by the first column of `ocel preview ls` (not the label) |
| `--folder /web` | the value in one variables folder |

`ls` lists values unrevealed, with the env source of each; `get --reveal` prints one; `source` also
shows what dev reads. Dev values are read locally by `ocel dev` and `ocel run`, so no `ocel env`
command addresses them.

With an [env source](/docs/env-sources) other than ocel's store, `set` writes into the source when
its `write` allows, else refuses and links to where to change it. `rm` always refuses: ocel never
deletes a key from an env source.

## Values in the build

| `ocel deploy` or `ocel build --env` builds | Gets |
| --- | --- |
| Next, as functions | every value, in its `build` script |
| Rust, as functions | every value, in `cargo build`, `build.rs` and proc macros |
| Go, Python or plain Node, as functions | none: the build runs none of your code |
| A [discovery folder](/docs/configuration#discoverypaths) | none: it runs before values resolve |
| Any app, as an image | sensitive and secret values and bindings; no plaintext |

`ocel build --env production` gets the values production holds now, and `--env preview` those of
the current branch's preview. It reads them without syncing the env source: for a source read on a
schedule, `ocel env sync` first picks up a change made there, and for one read where ocel runs, the
build gets what the last deploy copied. Its output deploys with `--prebuilt` only to the environment
it was built for. Without `--env`, `ocel build` reads no tier, so its output, and
`ocel deploy --prebuilt` of it, has no values. A preview build gets no app URL, so
`ocel preview up --prebuilt` refuses a Next build for a preview that has one.

### Functions

Plaintext values are in the build's environment. Sensitive and secret ones are files in a private
directory outside the project, which the SDK reads by itself, removed when the build ends, fails or
is interrupted. A Next build reading one needs Node 20.16+ or 22.3+. Resolved values win over your
shell's, and the build output prints `[secret]` in their place.

Cargo reruns `build.rs` only when what it watches changes:

```rust title="build.rs"
println!("cargo:rerun-if-env-changed=LOG_LEVEL"); // plaintext
println!("cargo:rerun-if-env-changed=OCEL_LIVE_DIR"); // sensitive or secret: new path every build
```

### Images

Plaintext values stay out, because an image keeps every `ARG` and `ENV`; the deploy warns for each
app that declares some. The rest arrive as build secrets, which never enter a layer or the image's
history. Never copy a value into an `ARG`, `ENV` or kept file yourself.

Bindings arrive over ports forwarded on your machine's `127.0.0.1`, so the reading step runs on the
host network. The docker daemon must share your machine's network (not a remote `DOCKER_HOST`,
nor a VM such as Docker Desktop's), and allow the `network.host` entitlement, which it does unless
`daemon.json` sets `"builder": { "entitlements": { "network-host": false } }`.

**Railpack** needs no change: the `build` step alone gets each value as a file in `/run/ocel-live`,
on the host network, and reruns when a value changes.

**A Dockerfile** mounts each value as a secret named after its key:

```dockerfile title="Dockerfile"
ARG OCEL_LIVE_HASH
RUN --mount=type=secret,id=OCEL_RESOURCE_POSTGRES_main,target=/run/ocel-live/OCEL_RESOURCE_POSTGRES_main,required=false \
    --network=host \
    OCEL_LIVE_DIR=/run/ocel-live pnpm run build
```

A bucket goes through the provider's binding proxy, whose address and token mount into the
environment (Dockerfile syntax 1.10+):

```dockerfile title="Dockerfile"
ARG OCEL_LIVE_HASH
RUN --mount=type=secret,id=OCEL_RUNTIME_ADDRESS,env=OCEL_RUNTIME_ADDRESS,required=false \
    --mount=type=secret,id=OCEL_SESSION_TOKEN,env=OCEL_SESSION_TOKEN,required=false \
    --network=host \
    pnpm run build
```

Keep `ARG OCEL_LIVE_HASH`: secret mounts don't change the cache key, and the hash does whenever a
value does. It is keyed with a random key in your ocel config directory, so `docker history` can't
be used to test a guessed value.

## Prerendered pages

A page prerendered from a value keeps it until the next deploy, even after you rotate the secret.
