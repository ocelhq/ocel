## Install

`ocel` is a single static binary. All three installs below ship the same build, and each replaces
an earlier install in place.

### Installer

macOS and Linux, on x86-64 and arm64:

```bash
curl -fsSL https://ocel.dev/install.sh | sh
curl -fsSL https://ocel.dev/install.sh | OCEL_VERSION=0.1.0 sh   # pin a version
curl -fsSL https://ocel.dev/install.sh | OCEL_CHANNEL=next sh    # or nightly
```

It verifies the download against the release's `checksums.txt` before writing anything, installs
into `~/.local/bin`, and prints the line to add to your shell profile if that isn't on `PATH`.
`next` is the newest release candidate, `nightly` the newest nightly build.

### Homebrew

```bash
brew install --cask ocelhq/tap/ocel
brew upgrade --cask ocel
```

Stable releases only: the tap has no release candidates or nightlies.

### npm

```bash
npm install -g @ocel/cli            # or @ocel/cli@next, @ocel/cli@nightly
npm install --save-dev @ocel/cli    # pin the CLI per project
```

The only install that covers Windows or pins per project. The binary comes as the optional
dependency for your platform, such as `@ocel/cli-linux-x64`, so nothing else is downloaded.

The `ocel` package your app imports for `postgres()`, `bucket()` and the config types is separate,
and contains no binary:

```bash
npm install ocel
```

### Check it

```bash
ocel --version
```
