```bash
ocel run -- pnpm test
ocel run --env production -- pnpm drizzle-kit migrate
```

Runs the command with your resources' connections, as files under `OCEL_LIVE_DIR` the way an app
gets them, so `postgres("main").connectionString` works in its code. The exit code is the
command's own.

## --env

| `--env` | Connects to |
| --- | --- |
| none | the dev resources `ocel dev` runs |
| `production` | the deployed production resources |
| `preview` | the current branch's preview |

With `--env`, `ocel run` opens a port forward to each resource through the provider, as
`ocel deploy` does for [`lifecycle.preBuild`](/docs/configuration#lifecycle), and closes them when
the command exits. It stops before the command starts when nothing is deployed there yet, or the
provider forwards no port.

The command gets the bindings only, not the project's variables. Secrets in them, such as a
database password, are hidden wherever the command prints them, so its output reaches your
terminal through `ocel run`'s pipes.
