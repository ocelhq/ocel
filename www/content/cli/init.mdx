```bash
ocel init --provider aws
ocel init my-app --provider vps
ocel init --provider gcp --option region=europe-west1
```

Writes the [config](/docs/configuration) and adds the ocel SDK with your language's package
manager. Entirely offline: it signs you into nothing and doesn't contact the console.

- `--provider` is required: `aws`, `gcp` or `vps`.
- The slug defaults to this directory's name.
- The config is `ocel.config.ts` in a project built with node and `ocel.json` in any other.
  `--format` picks [`yaml`](/docs/configuration#yaml), `json` or `ts` instead.
- `--option name=value` sets a provider option whose value is text; repeat it for each. `gcp`
  can't deploy without `region`, nor `vps` without `ssh`. On a terminal, init asks for the ones you
  leave out; under `--json` or with no terminal, it fails with
  [`input_required`](/docs/errors/input_required). A name the provider doesn't take is refused,
  naming the ones it does.

Then pin the providers this CLI runs, and commit the result:

```bash
ocel lock
```
