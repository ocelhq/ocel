# Domains across providers: CF-proxied `*.acme.com` with `*.nested.acme.com` on ACM

Ticket: ocelhq/ocel#396 (map: #390). Sources are the docs that own each fact; repo paths are at `9cb9b4cc`.

## Short answer

- Yes. A Cloudflare zone can proxy `*.acme.com` for the Worker edge and still serve `*.nested.acme.com` from ACM on CloudFront or API Gateway, in either of two DNS-only shapes: grey-cloud records in the Cloudflare zone, or NS delegation of `nested.acme.com` to a Route 53 hosted zone. A third shape — orange-cloud `*.nested.acme.com` proxied through Cloudflare onto CloudFront — also works but is the only one that costs money and interacts with the `*.acme.com` Worker route.
- Certificates: ACM public certs are free, valid 198 days, auto-renewed while the validation CNAME stays; a wildcard covers one level only, and `*.nested.acme.com` + `nested.acme.com` share one `_x.nested.acme.com` validation CNAME. CloudFront needs the cert in us-east-1; a Regional API Gateway domain needs it in the API's region. Default quota 10 names/cert (max 100), 2,500 certs/region.
- Cloudflare side: Universal SSL covers apex + one level, so nothing under `nested.acme.com` is TLS-terminable at Cloudflare without Advanced Certificate Manager (US$10/mo per zone; ≤50 SANs/cert; its wildcards also cover one level). In the two DNS-only shapes Cloudflare never terminates TLS for the nested names, so no ACM purchase.
- Wildcard overlap: Cloudflare's `*.acme.com` DNS record is multi-level and, on standard nameservers, answers `nested.acme.com` itself unless an explicit record or a delegation exists there; a `*.nested.acme.com` record (or an NS delegation) is the closest encloser for `x.nested.acme.com`, so it wins over `*.acme.com`. The Worker route pattern `*.acme.com/*` matches `x.nested.acme.com` (`*` = any chars) but only fires on proxied hostnames — irrelevant for grey-cloud/delegated, live in the proxied shape (a script-less route `*.nested.acme.com/*` negates it).
- Records per front: CloudFront ← `CNAME *.nested.acme.com → dxxxx.cloudfront.net` (or Route 53 A/AAAA alias, needed at an apex); API Gateway Regional ← `CNAME *.nested.acme.com → d-xxxx.execute-api.<region>.amazonaws.com` (or A alias with the region's hosted-zone id); Cloudflare Worker ← a proxied A/AAAA/CNAME at the hostname plus the route; Lambda Function URLs have no custom domain — a domain in `none` mode implies API Gateway.
- Validation CNAMEs `_x.nested.acme.com` must be DNS-only and not CNAME-flattened; both fronts route on the Host header, and CloudFront rejects a proxied hop with 421 unless SNI == Host and the served cert (same AWS account) covers it — so the proxied shape needs Full (strict) and an ACM cert for `*.nested.acme.com` on the distribution, and a CloudFront alt name at that level.
- Not established from primary sources: whether Cloudflare's `*.nested.acme.com` wildcard beats `*.acme.com` (Cloudflare documents only exact-record precedence; RFC 4592 closest-encloser gives the answer for compliant servers), Cloudflare's default origin SNI when no origin rule sets it, and any Cloudflare-published guide for fronting CloudFront (the old support article 404s).

## 1. Three shapes for `*.nested.acme.com`

| Shape | Nested records live in | Cloudflare terminates TLS for nested? | Worker route `*.acme.com/*` can fire on nested? | Extra cost |
| --- | --- | --- | --- | --- |
| A. grey-cloud in the Cloudflare zone | Cloudflare, DNS-only | no | no — routes need a proxied record | none |
| B. NS delegation to Route 53 | Route 53 hosted zone | no — "Cloudflare's CDN and security services are not applied to delegated subdomains" | no | US$0.50/zone/month; alias queries to CloudFront/API Gateway are free |
| C. orange-cloud in the Cloudflare zone | Cloudflare, proxied | yes — needs Advanced Certificate Manager | yes — negate with a script-less route | US$10/mo/zone |

Sources: DNS-only records "resolve to the record's actual origin IP address" and only A/AAAA/CNAME can be proxied — https://developers.cloudflare.com/dns/proxy-status/. Delegation: create NS records `blog.example.com NS ns1.externalhost.com` (≤10 NS), unavailable on CNAME (partial) setup, and services do not apply to delegated subdomains — https://developers.cloudflare.com/dns/manage-dns-records/how-to/subdomains-outside-cloudflare/. Route 53 side of delegation (create the hosted zone, copy its four NS into the parent, no SOA in the parent) — https://docs.aws.amazon.com/Route53/latest/DeveloperGuide/CreatingNewSubdomain.html. Route 53 pricing (US$0.50/hosted zone/month for the first 25; alias A/AAAA to CloudFront and API Gateway free) — https://aws.amazon.com/route53/pricing/. Worker routes: "All domains and subdomains must have a DNS record to be proxied on Cloudflare and used to invoke a Worker" — https://developers.cloudflare.com/workers/configuration/routing/routes/. Advanced Certificate Manager US$10/mo — https://www.cloudflare.com/plans/.

Repo touchpoints: the Cloudflare edge plants a proxied `AAAA 100::` at each routed hostname and refuses to attach a route under an unproxied record (`platform/edge/cloudflare/deploy/hostname.go:20-21`, `:202-215`, `:241-267`); it already warns when a hostname is more than one label below the zone (`platform/edge/cloudflare/deploy/hostname.go:52-54`, `:112-121`). Previews are one label under the base domain, `<project>--<preview>[--<app>].<domain>` (`cli/internal/cli/domain.go:32`), and `ocel domain use` takes the base, not the wildcard (`platform/aws/provider/server/server_domain.go:217-229`; `platform/edge/contract/sharedentry.go:36-41`).

## 2. Wildcard overlap

DNS in the Cloudflare zone. "A record `*.example.com` is already multi-level by default, meaning it would cover `abc.example.com` as well as `123.abc.example.com`"; "A wildcard record applies only when no exact record exists at the queried name. If a record or delegation exists, the wildcard does not apply"; with standard nameservers "a wildcard applies to parent labels lacking explicit records", while Advanced (Enterprise) nameservers follow RFC 4592 and do not — https://developers.cloudflare.com/dns/manage-dns-records/reference/wildcard-dns-records/. Consequences: (a) in shape A, `nested.acme.com` (the bare label) is answered by the proxied `*.acme.com` unless an explicit record is planted there, so the shared entry Worker sees it; (b) two wildcards at different depths: Cloudflare documents only exact-record and delegation precedence. RFC 4592 §3.3.1 defines the source of synthesis as the wildcard immediately under the closest encloser, and a wildcard "can be an empty non-terminal", so `*.nested.acme.com` makes `nested.acme.com` exist and captures `x.nested.acme.com` — https://www.rfc-editor.org/rfc/rfc4592#section-3.3.1. Route 53 behaves the same: `*.example.com` answers `zenith.example.com`, `acme.zenith.example.com`, …, specific names take precedence, and `*` cannot be used on NS records — https://docs.aws.amazon.com/Route53/latest/DeveloperGuide/DomainNameFormat.html#domain-name-format-asterisk.

Worker route patterns. "The only supported operator is the wildcard (`*`), which matches zero or more of any character"; `*.example.com/*` matches all subhosts and "the most specific route pattern wins"; "A route can be specified without being associated with a Worker. This will act to negate any less specific patterns" — https://developers.cloudflare.com/workers/configuration/routing/routes/. So `*.acme.com/*` (`platform/edge/cloudflare/deploy/hostname.go:142-144`, `platform/aws/provider/server/server_domain.go:245`) textually covers `x.nested.acme.com`; it is inert in shapes A/B (not proxied / not in the zone) and live in shape C unless a script-less `*.nested.acme.com/*` route is added.

CloudFront alternate domain names. `*.example.com` as an alt name matches `marketing.product-name.example.com` too — https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/alternate-domain-names-wildcard.html. An alt name cannot exist on two distributions; overlapping wildcard vs specific across distributions routes to the more specific name "regardless of the distribution that the DNS record points to"; distributions are selected by the `Host` header — https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/CNAMEs.html#alternate-domain-names-restrictions. Adding a more specific CNAME when a wildcard DNS entry already resolves to another distribution fails with "incorrectly configured DNS record" because CloudFront queries DNS for the name — https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/troubleshooting-distributions.html#troubleshoot-incorrectly-configured-DNS-record-error (a Cloudflare-proxied `*.acme.com` resolves to Cloudflare, not a distribution, so it does not trip this).

API Gateway. `*.example.com` and `a.example.com` can coexist in one account with different configurations; a wildcard custom domain cannot be created if another AWS account holds a conflicting name; "A custom domain name must be unique within a Region across all AWS accounts" — https://docs.aws.amazon.com/apigateway/latest/developerguide/how-to-custom-domains.html, https://docs.aws.amazon.com/apigateway/latest/developerguide/http-api-custom-domain-names.html.

## 3. Certificates

ACM public. "Public certificate (non-exportable)" — "No cost"; exportable ones are US$7/FQDN and US$79/wildcard — https://aws.amazon.com/certificate-manager/pricing/. Valid 198 days; wildcard "protects only one subdomain level" and not the apex; `example.com` + `*.example.com` go on one cert as two names; wildcards need DNS or email validation — https://docs.aws.amazon.com/acm/latest/userguide/acm-certificate-characteristics.html. DNS validation: one CNAME `_x.<name>` → `_y.acm-validations.aws`, identical for `*.example.com` and `example.com`, valid across Regions, keeps auto-renewal while in place, fails past five chained CNAMEs, and validation times out after 72 h — https://docs.aws.amazon.com/acm/latest/userguide/dns-validation.html. Quotas: 2,500 certificates (5,000 issued per year), 10 domain names per certificate by default (up to 100 on request) — https://docs.aws.amazon.com/acm/latest/userguide/acm-limits.html. Region: CloudFront viewer certs must be in us-east-1 — https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/cnames-and-https-requirements.html#https-requirements-aws-region; a Regional API Gateway domain's cert "must be in the same Region as your API" — https://docs.aws.amazon.com/apigateway/latest/developerguide/apigateway-regional-api-custom-domain-create.html. CloudFront checks the SAN at the same level: `*.example.com` authorises `product.example.com` but not `example.com` or `marketing.product.example.com`; `marketing.product.example.com` needs `*.product.example.com` or the exact name — https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/CNAMEs.html#alternate-domain-names-requirements. One cert per distribution; 100 alt names per distribution; no cert quota with SNI — https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/cloudfront-limits.html.

Cloudflare. Universal SSL covers the root and first-level subdomains, not `dev.www.example.com`; remedies are Advanced Certificate Manager (+ Total TLS or manual advanced certs) or a custom cert — https://developers.cloudflare.com/ssl/edge-certificates/universal-ssl/limitations/. Advanced Certificate Manager: paid add-on on all plans, "supports deep, multi-level subdomains", up to 50 hosts per cert with the zone apex as one of them, and "Wildcard certificates only cover one subdomain level" — https://developers.cloudflare.com/ssl/edge-certificates/advanced-certificate-manager/; US$10/mo — https://www.cloudflare.com/plans/. Total TLS issues per-hostname certs for proxied hostnames and requires ACM plus full DNS setup — https://developers.cloudflare.com/ssl/edge-certificates/additional-options/total-tls/. Wildcard records on a CNAME-setup zone get no automatic cert (TXT DCV per hostname) — https://developers.cloudflare.com/dns/manage-dns-records/reference/wildcard-dns-records/. Cloudflare publishes no separate "nested subdomain SSL" charge; the multi-level need is ACM's US$10/mo.

Validation records in a Cloudflare zone. The Amplify entry shows the pattern Cloudflare endorses for ACM: a DNS-only validation CNAME `<UNIQUE_STRING>` → `<UNIQUE_STRING>.mhbtsbpdnt.acm-validation.aws` with Flatten off, plus a CNAME to `<AMPLIFY_HOSTNAME>.cloudfront.net` — https://developers.cloudflare.com/dns/manage-dns-records/reference/vendor-specific-records/. Flattening: apex CNAMEs are always flattened; "Flatten all CNAMEs" and per-record flatten are paid-plan options; proxied records return Cloudflare anycast IPs; flattening a third-party verification CNAME can fail verification — https://developers.cloudflare.com/dns/cname-flattening/set-up-cname-flattening/, https://developers.cloudflare.com/dns/cname-flattening/.

## 5. The proxied hop (shape C) in detail

Cloudflare → CloudFront: CloudFront identifies the distribution by `Host` and, cross-account, rejects with 421 unless the SNI equals `Host`, the certificate belongs to the same account as the distribution, and `Host` is covered by the served certificate — https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/CNAMEs.html#alternate-domain-names-restrictions. Cloudflare's origin rules set SNI to the overridden `Host` when a Host override is applied and otherwise offer a static SNI override; the default SNI value is not stated on that page — https://developers.cloudflare.com/rules/origin-rules/features/. Full (strict) requires the origin cert to be unexpired, publicly trusted or Origin CA, and to match "the requested or target hostname" — https://developers.cloudflare.com/ssl/origin-configuration/ssl-modes/full-strict/ — which an ACM cert satisfies. Cloudflare's own CloudFront guide no longer exists (`/support/third-party-software/content-delivery-networks-cdns/configuring-cloudflare-and-amazon-cloudfront/` returns 404). CloudFront counts at most 2 distributions in a request chain, unrelated to a Cloudflare hop — https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/cloudfront-limits.html.

Cloudflare → API Gateway: a Regional custom domain routes on the hostname the client sent, so `Host` passthrough is enough; the same Full (strict) rule applies.

Net: shape C needs an ACM cert for `*.nested.acme.com` (AWS side, free), a Cloudflare advanced cert covering `*.nested.acme.com` (US$10/mo), Full (strict), and a script-less `*.nested.acme.com/*` route if the shared entry Worker must not intercept nested traffic. It buys nothing an Ocel mode wants over shape A, so the DNS axis can enumerate A and B and print C only as a caveat.
