# CloudFront previews and resolution: SaaS Manager vs wildcard distribution, Functions + KVS

Ticket: ocelhq/ocel#392 (map: #390). Primary sources only; every claim carries its owner.

## Short answer

- Wildcard distribution + CloudFront Function + KeyValueStore is the workable shape. A KVS write is a global, ETag-conditioned, all-or-nothing `UpdateKeys`; AWS states edge propagation as "a few seconds" in prose only — no numeric bound, no SLA — so print the rollback SLA as *seconds, unguaranteed*, not "instant".
- KVS limits: key 512 B, value 1 KB, store 5 MB, 1 store per function, 200 stores per account, 50 keys / 3 MB per write call. A hostname → {promotion, origin host} pointer fits; today's `DeploymentRecord` (routing manifest + per-route function URL map) does not.
- A viewer-request CloudFront Function *can* change the origin per request: `cf.updateRequestOrigin({domainName, originPath, customHeaders, originAccessControlConfig, timeouts, ...})` takes "any HTTP endpoint" that need not be a configured origin; `selectRequestOriginById` picks a configured one; `createRequestOriginGroup` builds a failover pair. Viewer-request only, runs on every request (cached or not), no VPC origins.
- Function ceiling: 10 KB code (not adjustable), 2 MB memory, no network/filesystem/timers/request body, 100 functions per account. Route-level dispatch across a Next routing manifest does not fit; the function picks *one origin per hostname* and that origin (a per-deployment Lambda URL or a shared router) does the rest.
- Cost per request for (2): $0.10 per 1M function invocations + $0.03 per 1M KVS reads (2M invocations/month free); KVS control-plane calls $1 per 1,000.
- OAC to a Lambda function URL requires the *client* to send `x-amz-content-sha256` on PUT/POST ("Lambda doesn't support unsigned payloads") — a browser POST through CloudFront to an `AWS_IAM` function URL fails as the provider configures URLs today. This is the load-bearing origin-auth fact for native mode.
- SaaS Manager: 20 multi-tenant distributions and 10,000 tenants per account (adjustable), 100 aliases per tenant, parameters only in origin domain and origin path (≤ 2 per field). Tenants inherit the parent's wildcard ACM cert; otherwise a CloudFront-managed HTTP-validated cert is issued asynchronously, one pending request per tenant. No per-tenant provisioning latency is published; a tenant is distribution config that propagates like any change ("a matter of a few minutes" typical) and may briefly serve older config — not a seconds-scale per-preview primitive. Pricing: first 10 tenants free, 11–200 a $20 monthly subscription, then $0.10 per tenant per month.
- Not established from primary sources: KVS write-API rate limits, a numeric KVS propagation bound, tenant create/update propagation time, and whether `updateRequestOrigin` is honoured under a multi-tenant distribution.

## 1. Wildcard distribution: aliases, certificate, request identification

- A wildcard alias must begin with `*.`, cannot replace part of a label or a middle label, and "must be covered by the subject alternative name (SAN) on the certificate"; `*.example.com` serves `www.example.com` and `marketing.product-name.example.com` alike. https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/alternate-domain-names-wildcard.html
- The *certificate* wildcard authorises one label level: with `*.example.com` "you can't add the alternate domain names example.com or marketing.product.example.com". One certificate per distribution. https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/CNAMEs.html#alternate-domain-names-requirements
- Uniqueness: an alias cannot exist in two distributions, but a wildcard may overlap a more specific alias in another distribution and "CloudFront sends the request to the distribution with the more specific name match, regardless of the distribution that the DNS record points to". https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/CNAMEs.html#alternate-domain-names-restrictions
- Domain-fronting guard: SNI must equal `Host`, the cert must belong to the distribution's account, and `Host` must be covered by the served cert, else 421. Preview hostnames as single labels under the wildcard satisfy all three. Same section.
- The preview label already assumes one label under a base: `PreviewLabel` joins slug/pointer/app with `--` and caps at 63 chars — platform/edge/contract/previewlabel.go:8-26.
- Quotas: 500 distributions per account, 100 aliases per distribution, 100 origins per distribution, 10 origin groups per distribution, 75 cache behaviors (all adjustable). https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/cloudfront-limits.html#limits-web-distributions
- Config propagation: "changes are propagated to the edge in a matter of a few minutes, and invalidation times are under two minutes" — the only numeric statement AWS makes, on the features page. https://aws.amazon.com/cloudfront/features/ — the developer guide gives no number and warns that during propagation "we can't determine whether a given edge location is serving your content based on the previous configuration or the new configuration". https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/HowToUpdateDistribution.html

## 2. KeyValueStore

- Limits: key 512 B, value 1 KB, store 5 MB, ≤ 50 keys or 3 MB per update call, ≤ 10 functions per store, 1 store per function, 200 stores per account (adjustable). https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/cloudfront-limits.html#limits-keyvaluestores
- Write API: `PutKey`, `DeleteKey`, `UpdateKeys` (puts + deletes "in one all-or-nothing operation"), each conditioned on the store `ETag` from the KVS `DescribeKeyValueStore` (`--if-match`); a global service signed with SigV4A that needs v2 session tokens (regional STS endpoint). https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/kvs-with-functions-kvp.html ; https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/cloudfront-function-restrictions.html#regional-endpoint-for-key-value-store
- Read semantics: values "aren't updated or changed during the invocation of the function. Updates are processed in between invocations". https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/kvs-with-functions-kvp.html#kvs-with-functions-api-describe
- Propagation: the developer guide states no number; `meta().lastUpdatedDateTime` "doesn't include the propagation time to the edge", so propagation is asynchronous and unobservable from the function. https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/functions-custom-methods.html#functions-custom-methods-meta — the launch post says "changes are propagated to all CloudFront edge locations in a few seconds". https://aws.amazon.com/blogs/aws/introducing-amazon-cloudfront-keyvaluestore-a-low-latency-datastore-for-cloudfront-functions/
- Helpers: `cf.kvs().get(key, {format: string|json|bytes})`, `exists`, `meta`; `get` throws on a missing key; AWS advises sequential `await` over `Promise.all` (memory). https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/functions-custom-methods.html
- KVS requires JS runtime 2.0; reads from a function are not CloudTrail data events. https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/kvs-with-functions.html
- Fit against the ledger: `DeploymentRecord` carries `RoutingManifest`, `FunctionURLs map[string]string`, env, variables — platform/edge/contract/rootstack.go:71-88; the entry worker dispatches per route target to `functionUrls[target.id]` — platform/edge/cloudflare/workers/entry/src/index.ts:1094,1265,1694. Under a 1 KB value and a 10 KB function only the *pointer* (hostname → promotion/origin host) belongs in KVS; the record stays in the origin-provided ledger (DynamoDB per #390 "Settled while charting").
- Rollback SLA to print: one conditional `UpdateKeys`; propagation "a few seconds", no published bound, no SLA.

## 3. CloudFront Functions and per-request origin selection

- Origin-modification helpers exist on *viewer request* only, JS runtime 2.0: `updateRequestOrigin`, `selectRequestOriginById`, `createRequestOriginGroup`. The test console does not exercise them. https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/helper-functions-origin-modification.html
- `updateRequestOrigin`: "can be any HTTP endpoint and doesn't need to be an existing origin within your CloudFront distribution"; unspecified fields inherit the assigned origin; fields: `domainName`, `hostHeader`, `originPath`, `customHeaders`, `connectionAttempts`, `originShield`, `originAccessControlConfig{enabled, signingBehavior, signingProtocol: sigv4, originType: s3|mediapackagev2|mediastore|lambda}`, `timeouts`, `customOriginConfig{port, protocol, sslProtocols, ipAddressType}`, `sni`, `allowedCertificateNames`. Cannot target VPC origins; on an origin group only the primary is replaced. Same page.
- `selectRequestOriginById(id, {hostHeader, sni, allowedCertificateNames})` only for origins configured in the distribution (VPC and mTLS origins allowed). `createRequestOriginGroup({originIds:[primary, secondary], failoverCriteria})` from configured origins. Same page.
- The function runs on every request including cache hits ("this logic will run on every request"); AWS positions Functions for dynamic always-to-origin traffic and Lambda@Edge for cacheable traffic (Lambda@Edge is off the table per #390). Same page, "Choose between".
- Runtime ceiling: 10 KB code ("isn't adjustable"), 2 MB memory, 100 functions per account, 100 distributions per function; no network, file system, env vars, timers, dynamic eval, request body; a compute-utilization time cap. https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/cloudfront-limits.html#limits-functions ; https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/cloudfront-function-restrictions.html
- Rewriting `uri` "doesn't change the cache behavior for the request or the origin". Header names are lowercased in the event. https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/functions-event-structure.html#functions-event-structure-request
- Consequence: per hostname the function reads one KVS key and calls `updateRequestOrigin` toward that deployment's single origin (or sets a header and leaves a shared router origin). Route-level dispatch to many function URLs per deployment cannot live in the function.

## 4. Origin auth toward Lambda function URLs

- OAC to a Lambda function URL: `AuthType` must be `AWS_IAM`; permission via `lambda:InvokeFunctionUrl` (and `lambda:InvokeFunction`) for `cloudfront.amazonaws.com` scoped by `SourceArn` to the distribution. "If you use PUT or POST methods with your Lambda function URL, your users must compute the SHA256 of the body and include the payload hash value of the request body in the x-amz-content-sha256 header when sending the request to CloudFront. Lambda doesn't support unsigned payloads." https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/private-content-restricting-access-to-lambda.html
- Today's app function URLs are `AWS_IAM` — platform/aws/provider/deploy/function.go:41,466 — and the Cloudflare edge signs the body itself with aws4fetch — platform/edge/cloudflare/workers/entry/src/signing.ts:1-40. CloudFront cannot do that on the viewer's behalf; native mode needs a different origin auth for non-GET traffic (public URL + secret custom header via `updateRequestOrigin.customHeaders`, or an API Gateway/router front). https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/helper-functions-origin-modification.html
- Origin selection also works for S3 with OAC (`originType: s3`) from the same function, so assets and the app can share one behavior. Same page, S3 example.

## 5. Pricing

- Functions $0.10 per 1M invocations, 2M/month always free; KVS $0.03 per 1M reads from functions, $1 per 1,000 other KVS API requests; SaaS Manager: first 10 tenants free, 11–200 tenants $20 subscription, over 200 $0.10 per tenant; invalidations 1,000 paths free then $0.005; dedicated-IP SSL $600/month (moot: tenants are SNI-only). https://aws.amazon.com/cloudfront/pricing/pay-as-you-go/

## 6. SaaS Manager (multi-tenant distributions)

- Model: a non-routable multi-tenant distribution (template) + connection group (routing endpoint `dxxx.cloudfront.net`) + distribution tenants, each with ≥ 1 domain, inheriting config; per-tenant overrides: parameters, WAF v2 web ACL, geo restrictions, custom ACM cert, invalidation paths. https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/distribution-config-options.html ; https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/tenant-customization.html
- Parameters: usable only in origin domain name and origin path, ≤ 2 per property, e.g. `{{p}}.lambda-url.us-east-1.on.aws`. Same page. A tenant can therefore point at a per-deployment function URL — but re-pointing is `UpdateDistributionTenant`, a config propagation, not a data flip.
- Quotas: 20 multi-tenant distributions, 10,000 tenants, 100 connection groups per account, 100 aliases and 5 parameters per tenant (all adjustable). https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/cloudfront-limits.html#limits-template
- Certificates: a tenant "inherits the shared AWS Certificate Manager (ACM) certificate from the multi-tenant distribution"; wildcard domains on tenants are supported when the parent's shared cert (or a custom tenant cert) covers them; otherwise CloudFront requests an HTTP-validated managed cert (`ManagedCertificateRequest`), one pending request per tenant, domain inactive until validated; certs must be in us-east-1. https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/managed-cloudfront-certificates.html
- Provisioning latency: `CreateDistributionTenant` returns a `Status` string; no propagation figure is published. https://docs.aws.amazon.com/cloudfront/latest/APIReference/API_CreateDistributionTenant.html — the update guide adds that "some distribution tenant traffic might be served using older configurations for a brief period". https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/HowToUpdateDistribution.html
- Unsupported on multi-tenant: continuous deployment, OAI, dedicated IP, WAF classic, legacy logging, min/default/max TTL, ForwardedValues, PriceClass, trusted signers, IAM certs, SSLv3. https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/distribution-config-options.html#unsupported-saas
- Functions do run under multi-tenant distributions (event `context.endpoint` replaces `distributionDomainName`). https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/functions-event-structure.html#functions-event-structure-context — whether the origin-modification helpers are honoured there is stated nowhere found.
- Domain move: an active tenant domain "can't be deactivated"; moving it needs `UpdateDomainAssociation`. https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/managed-cloudfront-certificates.html#tenant-domain-considerations
